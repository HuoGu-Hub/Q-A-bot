# 检索黄金集（retrieval goldenset）

回答质量的**回归基线**。没有它，所有"口语问答变好了"的说法都只能靠感觉。

## 怎么跑

跑手是一个普通 JUnit 测试：

```bash
# 宿主（隔离构建，不会写 server/target）
./scripts/build-server.sh -q '-Dtest=RetrievalGoldenTest' test
```

它会：

1. **复制**一份 `server/data/qa/qqbot.sqlite` 到临时目录再读（绝不直接读生产库 —— WAL 共享内存会冲突，且迁移会写库）；
2. 用**真实生产参数**（`top-k=5`、`min-score=0.45`、`title-gate=0.70`）走**真实检索器** `KbRetriever`；
3. 分类统计并打印 R@1 / R@5 / MRR / 干净率。

没有生产库、或不在工程内时会**跳过**（`Assumptions`），不会让别的机器构建失败。

> 向量路需要 `.env` 里的 `SILICONFLOW_API_KEY`（42 条查询约 42 次 embedding 调用）。
> 拿不到 key、或调用失败时，跑手会明确打印"本次只跑本地关键词路"，**并自动关掉回归门槛** ——
> 因为那测的是另一种分布，拿它卡门槛只会变成假红。

## 四类为什么必须分开

混在一起算平均值会**掩盖问题**：

```
                   重排前                          重排后（当前默认）
类别          条数    R@1     R@5     MRR     干净率     R@1     MRR      干净率   注入块均值
entity         12   66.7%  100.0%  0.819      -       91.7%  0.938       -        5.0
colloquial      2   50.0%  100.0%  0.708      -      100.0%  1.000       -        5.0
gap             5      -       -       -     0.0%        -      -       0.0%      5.0
chitchat       15      -       -       -     6.7%        -      -      93.3%      0.3
descriptive     8      -       -       -       -         -      -         -         -
```

**最重要的一行**：`gap + chitchat` 注入的垃圾块从 **95 → 30**（其中 25 块来自尚未解决的 `gap`）。

`entity` 类接近满分、`gap` 类全错，平均下来"看着还行"，但群友体感就是**一问位置就胡说**。

```bash
# 关掉重排跑（做前后对比）：会按"重排前"的较低门槛检查
mvn '-Dqqbot.golden.rerank=off' '-Dtest=RetrievalGoldenTest' test
```

### 为什么不能靠"调高 min-score"解决

实测发现四类的 `bestCosineRaw` **分布完全重叠**：该答的 entity 最低 0.548，
而库里根本没有的 gap 最高 0.559，一条闲聊甚至到 0.634。单一绝对值阈值必然两头不讨好。

正解是 cross-encoder 重排：闲聊顶分 ≤0.002、真实问题 ≥0.04，才有可分性。
详见 [知识库口语问答重构方案 5.1.1 / 5.1.2](../../docs/md/知识库口语问答重构方案.md)。

## 四类的语义

| 类别 | 含义 | 指标 |
|---|---|---|
| `entity` | 报名字提问，语料里有对应词条 | R@1 / R@5 / MRR |
| `colloquial` | 玩家用**俗称**，语料里是官方译名 | R@1 / R@5 / MRR |
| `gap` | 真实游戏问题，但语料里**根本没有** | 干净率（返回空的比例，越高越好） |
| `chitchat` | 与知识库无关 | 干净率 |
| `descriptive` | 描述需求式提问 | **待人工标注**（`expected = ?`，跑手打印 Top-5 供判定） |

`gap`/`chitchat` 的正确行为是**一个块都不注入**。注入了 5 块"看着相关其实无关"的资料，
比返回空更糟 —— 模型会被这些资料带偏。

## 怎么加条目

`retrieval-golden.tsv`，制表符分隔，`#` 开头是注释：

```
category<TAB>question<TAB>expected_block_ids<TAB>note
```

- `expected` 用 `;` 分隔多个可接受答案（如 `advanced-glider;extraordinary-glider`）；
- `-` 表示期望不检索到任何块；
- `?` 表示尚未人工标注（只打印，不打分）。

## ⚠️ 标注踩过的坑（实测）

标注错了会**看着像系统错**。首轮就踩了三个：

| 问题 | 首轮标注 | 实际 | 教训 |
|---|---|---|---|
| 咖啡豆的那个烘培器怎么弄 | `coffee-beans` | `coffee-drum-roaster`（咖啡滚筒烘焙机） | 问的是"烘培器"不是"咖啡豆"，读题要读全 |
| 氨液腺这个一般都在哪啊 | `gap` | `ammonia-gland`（**氨腺**） | 玩家说"氨液腺"，关键词路 0 命中，**靠向量路第 3 名捞回** |
| 那个电法师头在哪拿来着 | `gap` | `archmage-hat`（**大法师帽**） | 纯口语指代，向量路第 1 名 |

后两条尤其重要：它们**不是** gap，是 `colloquial` —— 是向量路的胜利，
标成 gap 会把功劳记成过失。

## 已知未覆盖

`descriptive` 类（6 条）**尚未人工标注**，是目前最大的空白。
它恰恰最贴近用户痛点（"怎么快速回血"、"有没有加移速的鞋"），但正确答案需要懂游戏的人判定。
自动标注会把这批样本标成"无解"，从而掩盖真实缺口，所以必须人工来。
