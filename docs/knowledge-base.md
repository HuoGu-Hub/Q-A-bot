# 知识库

## 1. 数据模型

知识库的最小单位是块。一个块同时是一个词条：`id + 标题 + 别名`。

| 字段 | 说明 |
|---|---|
| `id` | 块身份，数据库主键。只允许英文字母、数字与连字符 |
| `docId` | 所属文档或页面，用于整份替换、分组与去重 |
| `title` | 中文标题 |
| `body` | 中文正文，是送进向量与提示词的内容 |
| `url` | 原文出处，回答时可作为来源展示 |
| `tags` | 分类标签 |
| `source` | `doc` 文档导入、`manual` 管理端手写、`wiki` 抓取 |
| `retired` | 下架标记。下架后不参与检索，数据保留 |
| `alias` | 人工维护的别名。导入不会覆盖 |

块与向量分表存储：

| 表 | 内容 |
|---|---|
| `kb_block` | 块正文、来源、下架状态、别名 |
| `kb_block_vec` | 正文向量 BLOB |
| `kb_block_title_vec` | 标题向量 BLOB，用于 C 路闸门 |
| `kb_category` | 分类 |
| `kb_wiki_page` | wiki 页面同步状态与 revid |
| `kb_wiki_source` | wiki 抓取范围 |

使用行号作为块身份会让删除与重排失效，因此现行设计以 `id` 为唯一身份。删除就是删除，不需要墓碑。

## 2. 文档格式

系统只接受符合规范的文档，抓取、清洗与翻译都在系统外完成。校验命令：

```bash
./scripts/validate-kb-doc.sh 文件.md
```

### 2.1 文档头

放在文件最前面，可选但强烈建议：

```markdown
<!-- doc
name: 灵火祭坛
source: wiki
url: https://enshrouded.wiki.gg/wiki/Flame_Altar
tags: 基础, 据点
-->
```

| 字段 | 必填 | 用途 |
|---|---|---|
| `name` | 是 | 文档身份，块按它归组 |
| `url` | 建议 | 原文地址，回答时作为出处 |
| `tags` | 建议 | 分类标签，逗号分隔 |
| `source` | 可选 | 来源标记 |
| 其他 | 可选 | 原样保留，导入流程不消费 |

首行必须恰好是 `<!-- doc`，且必须有闭合的 `-->`。缺少闭合会把后续正文吞进文档头，表现为导入后块数变少。

### 2.2 分块

```markdown
=== 灵火祭坛 === <!-- id: flame-altar-0 -->
灵火祭坛是复活点。死亡后会在最近的祭坛复活。

=== 升级材料 === <!-- id: flame-altar-1 -->
升级需要 5 个瘴气木和 3 个树脂。
```

| 规则 | 说明 |
|---|---|
| 等号数量 | 1 到 8 个都可以，左右必须一致。不一致时当普通正文 |
| 标题 | 自动去掉前后空格。正文中的分隔符行可用行首 `\` 转义 |
| id | 只允许 `[A-Za-z0-9-]+`。可选，但推荐每块都写 |
| 唯一性 | 同一文档内 key 必须唯一。有 id 用 id，没有 id 用标题 |
| 标题重复 | 只提醒，不阻断 |
| 正文为空 | 校验器提醒 |

### 2.3 配图

块可以带一张图，由正文中的标记决定：

```text
[[img:kb:acid-cleaver]]
```

| 规则 | 说明 |
|---|---|
| 来源 | `kb` 对应 `data/kb-images/` |
| 名字 | 图片文件名去掉扩展名，建议使用块 id |
| 位置 | 建议放在块尾单独一行 |
| 缺失 | 名字对不上时不报错，只是不配图 |

出站层会把标记替换为真实图片。模型只负责原样抄写标记，不负责拼路径。

### 2.4 内容要求

| 要求 | 说明 |
|---|---|
| 一块一件事 | 块是检索单位，混入多个主题会导致答非所问 |
| 保留事实 | 数值、配方、材料、位置、掉落、解锁条件不能漏 |
| 去掉噪音 | 导航、页脚、侧栏、广告、评论区、相关链接 |
| 去掉模板痕迹 | 例如 `Infobox/Skill: title: ... ; ID: ...` |
| 不编造 | 原文没有的内容宁可不写 |
| 长度 | 单块建议 40 到 1600 字 |
| 语言 | 标题与正文用中文，id 用英文，URL 保持原样 |

合规模板见 `docs/samples/kb-doc-ok.md`，违规示例见 `docs/samples/kb-doc-bad.md`。

## 3. 导入语义

`KbDocImporter` 是系统内唯一的文档导入入口。

| 情形 | 行为 |
|---|---|
| id 已存在 | 覆盖 |
| id 不存在 | 新增 |
| 文档中未出现 | 保持不动 |
| 人工修改过的块 | 同样以最新导入为准 |
| 同一文档导入两次 | 第二次不产生变化 |

导入分两步：

1. 预览：只计算会新增、覆盖、不变、未触及的数量，不写库。
2. 导入：写入并只为新增或修改的块计算向量。

标题向量可单独补建。管理端提供「补标题向量」按钮，命令行入口为 `KbTitleVectorRunner`。

## 4. 摄入通道

| 通道 | 入口 | 产物 | 可回滚 |
|---|---|---|---|
| 手写或外部整理的文档 | 管理端「知识库 → 文档」导入 | `source=doc` 块 | 按文档下架或删除 |
| 管理端手写 | 管理端「知识库 → 文档」新增 | `source=manual` 块 | 删除块 |
| wiki 文章 | 管理端「知识库 → 抓取」 | `source=wiki` 块 | 强制重洗，或在同一页面回滚 |
| 地图点位 | 地图同步后派生地点语料 | 地点与 NPC 块 | `location-corpus.purge` |

wiki 抓取有三种模式：空跑只统计数量，增量只处理 revid 变化的页面，强制重洗忽略 revid。清洗规则变更后使用强制重洗，因为增量判据是页面版本而不是本地规则版本。

地图同步拉取 Map 命名空间中的全部页面，启用哪几张由 `kb_map_active` 决定。同步完成后可派生地点语料；派生只读取已入库的点位，不再访问 wiki。

## 5. 词条与分类

一个块就是一条词条。标题末尾的「（English）」会被拆成别名：

```text
=== 深渊之翼斧（Abyssal Wing Axe） === <!-- id: abyssal-wing-axe -->
词条：深渊之翼斧、Abyssal Wing Axe
```

别名用于关键词路匹配。群友只会说中文名，不会说完整标题。人工核对过的别名优先于标题派生值，导入不会覆盖别名。

分类保存在 `kb_category`，用于公开站筛选与后台管理。分类是展示维度，不参与检索打分。

## 6. 激活与缓存

块表写入成功后版本号加一。索引快照、检索缓存、公开站搜索结果与分类统计都按版本失效，下一次检索自动读取新语料，不需要重启。

命令行任务运行在独立进程，结束后服务下一次检索即生效。管理端触发的导入在当前进程内立即生效。

## 7. 运维命令

完整命令集中在 [deployment.md](deployment.md)。知识库相关部分：

```bash
# 校验文档格式，不启动服务、不连数据库
./scripts/validate-kb-doc.sh 文件.md

# 检索回归
./scripts/golden-gate.sh
./scripts/golden-gate.sh --rerank off

# 地图同步，增量
java -jar server/target/qqbot-server-*.jar \
  --app.kb.map-sync.sync-on-start=true --spring.main.web-application-type=none

# 由已同步的点位派生地点语料
java -jar server/target/qqbot-server-*.jar \
  --app.kb.location-corpus.build-on-start=true --spring.main.web-application-type=none

# 回滚地点语料
java -jar server/target/qqbot-server-*.jar \
  --app.kb.location-corpus.build-on-start=true \
  --app.kb.location-corpus.purge=true \
  --spring.main.web-application-type=none
```

wiki 文章导入与回滚的主入口都是管理端「知识库 → 抓取」页面，没有对应的命令行开关。页面可以选择范围、空跑、增量、强制重洗或回滚。

## 8. 语料目录

`corpus/gamedata/` 存放示例语料与来源数据：

| 路径 | 内容 |
|---|---|
| `*.md` | 已整理的中文文档，可直接导入 |
| `_source/*.json` | 原始条目数据 |
| `index/*.tsv`、`index/*.jsonl` | 由来源数据生成的索引 |

示例语料来自 `enshrouded.wiki.gg`，仅用于演示与本地验证。二次分发前应确认来源站点的许可条款。

## 9. 约束与常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 导入后块数变少 | 文档头缺少 `-->`，后续正文被吞 | 用校验器检查 |
| 少了一块 | 分隔符左右等号数量不一致 | 数一遍两边的等号 |
| 标题重复导致无法导入 | 两块都没写 id 且标题相同 | 给每块补唯一 id |
| 中文名提问搜不到 | 语料正文为英文，标题向量未覆盖 | 补标题向量；确认术语表有对应中文名 |
| 配图不显示 | 标记名字与文件名不一致 | 用块 id 作图片名，重新导入 |
| 修改语料后检索无变化 | 导入未成功，或查看的是旧结果 | 查看块数与语料版本日志，重新提问验证 |
| 公开站结果被去重 | 同一页面切成多块 | 属于预期行为，公开站按文档去重 |
