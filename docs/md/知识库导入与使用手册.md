## 二、导入文档（主要入口）

管理端 → **知识库 → 文档**（这个 tab 是第一个，也是默认落点）。

### 步骤

1. **准备文档**：按 `知识库文档格式规范` 产出（标题中文、id 英文、正文翻译成中文）。
   产出后**先自查**：

   ```bash
   ./scripts/validate-kb-doc.sh 你的文档.md
   ```

   退出码 0 才算合格。这一步别跳 —— 格式问题在这里最便宜。

2. **粘贴或选文件**（支持 .md / .txt）。

3. **点「预览会改什么」** —— 只算不改，告诉你：

   ```
   新增 N   覆盖 M   无变化 K   库里未被触及 X 块
   新增：id1、id2…     覆盖：id3…
   ⚠️ 提醒：…
   ```

   看三个数：
   - **覆盖 M** 应该约等于"这次改了几块"。若等于整份文档的块数，说明 **id 变了**；
   - **新增 N** 里出现"标题和库里某块相同但 id 不同"的提醒 → 几乎一定是 id 写错了，
     导进去会变成重复两块；
   - **未被触及 X** 是库里没被这次导入碰到的块数。

4. **点「确认导入」** —— **导入即生效**（索引自动重载，不用重启）。

### 导入规则（就一条）

> 文件里出现的块：**id 存在 → 覆盖；不存在 → 新增**。
> 文件里没出现的块：**一个都不动**。
> 不区分是否人工改过，一律以最新导入的为准。

所以**更新时只给改动过的几块**是完全支持的，也正是推荐的用法。

## 三、导入术语表

术语表是**人工成果**（2026-10-08 实测 3,439 条，其中 2,772 条含中文名；条数随语料增减），导入要小心。

### 格式

**在 Excel / WPS 里编辑 `.xlsx`，改完直接导回** —— 后台「词条」面板的「导出」拿到的就是 xlsx。
**第一行是表头**，列名认这些（中英文都认）：

| 列 | 认得的写法 | 必需 |
|---|---|---|
| 英文名 | `英文名` / `英文` / `en` / `id` / `english` / `页面` | 是 |
| 中文名 | `中文名` / `中文` / `zh` / `chinese` / `译名` | 是 |
| 别名 | `别名` / `别称` / `alias` / `aliases` | 可选 |
| 状态 | `状态` / `status` | 可选（默认 draft） |

例（**只给改动过的那几行也可以**）：

| 英文名 | 中文名 | 别名 | 状态 |
|---|---|---|---|
| Kiln | 熔炉 | 炉子 | verified |
| Flame Altar | 灵火祭坛 | 祭坛、圣坛 | verified |

> ⚠️ **为什么改用 xlsx、不再推荐 CSV**：中文 Windows 上 Excel / WPS「另存为 CSV」默认是 **GBK**，
> 而浏览器读文件固定按 **UTF-8** 解码 → 中文变乱码**而且不报错**，直接污染词条表。
> xlsx 内部就是 UTF-8 的 XML，**没有编码这回事**。
> 导出的 CSV 已于 2026-10-08 删除（接口 `format=csv` 现在会**明确报错**，不会悄悄换成 xlsx）。

**别名不用单开一列存** —— 库里「别名」本来就是中文名用 `、` 分隔的若干写法，
导入时自动合并去重。所以 `Kiln` 存进去就是 `熔炉、炉子`。

### 注意

- **导入是「覆盖」，以最新导入为准** —— 同一份文件导两次不产生重复行，但**已存在的行会被文件里的值覆盖**。
  只想动几行，就只导那几行（key 是**英文名**）。
  与之相对，**按语料自动补齐**（新块自动获得一条空词条）走的是 `INSERT OR IGNORE`，一个字都不动 ——
  那是为了保护人工成果，**两者别搞混**。
- **旧的无表头 TSV 也还能导**（按列位置认，状态在第 5 列）；`.csv` / `.tsv` 导入侧仍然收，
  并且会剥 BOM、用 `U+FFFD` 拦截明显的乱码文件（但能用 xlsx 就别用 CSV）；
- 保存即生效（词表按版本号自动感知，不用重启）；
- 入口：管理端 → 知识库 → 词条 → 「导入」。

## 四、改已经导进来的内容

两条路，各有适用场景：

| 想做什么 | 怎么做 |
|---|---|
| **改正文** | 「文档」面板 → 展开文档 → 该块「编辑」→ 保存（**会自动重算这一块的向量**） |
| **下架某块** | 「文档」面板 → 该块「下架」（保留数据，可恢复） |
| **删除某块** | 「文档」面板 → 该块「删除」（物理删除，不可恢复） |
| **整份下架** | 「文档」面板 → 文档行「整份下架」 |
| **改名字/别名** | 「词条」面板（词条只管**名字**，不管正文） |
| **首屏清空重来** | 「文档」面板 → 「清空全部块」（不可逆，会二次确认） |

> ⚠️ 改正文**必须**走「文档」面板 —— 因为只有那里会重算向量。
> 只改文本不重算向量，检索会按旧正文匹配，改了等于没改。

## 五、验收脚本

界面的自动化验收脚本（需要宿主的前端 dev 或后端在跑）：

```bash
node tests/verify-kb-docs-panel.js
# 或指定地址
BASE=http://localhost:8080 node tests/verify-kb-docs-panel.js
```

它验 12 件事，包括：默认落在「文档」tab、概览数字、**预览调的是 preview 而不是 import**、
预览里的 id 提醒会显示、确认导入的请求体、展开文档看到块、改正文的请求体、
下架/删除、**删除和清空都要弹二次确认**、0 console error。

> 写这个脚本时宿主服务停着，所以**它还没被真正跑过**；起服务后跑一遍，不过我再修。

## 六、给外部 AI 的交付要求（一句话版）

> 按 `知识库文档格式规范.html` 产出：**标题中文、id 英文**（`页面名-序号`），
> 每块一个唯一 id，正文翻译成中文，去掉导航/页脚/模板痕迹，保留全部数值与配方。
> 产出后跑 `./scripts/validate-kb-doc.sh 文件.md`，**退出码必须是 0**。
>
> 更新时**只给改动过的块**即可 —— 没给的那些系统一个都不会动。
