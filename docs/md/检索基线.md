## 〇·二、批次推进记录

扩充语料**分批做**，每批之后跑一次黄金集，门槛没掉再放开下一批（`app.kb.wiki-import.categories`）。

### 批次 1（2026-10-04）—— Quests/ + 基础 + 技能 + Wildlife

**导入**：373 页 → **403 块**，20.4 万字，0 失败。语料 **2,649 → 3,052 块（+15.2%）**。

| 类别 | 导入前 | 导入后 |
|---|---|---|
| entity R@1 / R@5 | 73.3% / 93.3% | **75.0% / 93.8%** |
| colloquial R@1 | 100.0%（n=3） | **100.0%（n=4）** |
| chitchat 干净率 | 93.3% | **93.3%** |
| gap 干净率 | 31.6%（n=19） | **29.4%（n=17）** |

**受门槛的三类无退化** ✓。`gap` 在**同 17 条**上是 23.5% → 29.4%（改善）。

#### ★ 这一批真正的成果：**2 条 gap 变成了可回答**

| 提问 | 新块 | 正文 |
|---|---|---|
| 正常的话满技能点是多少 | `wiki-skill-points` | "you can obtain **88 Skill Points** leveling from 2-45" |
| 黑魔法是什么 | `wiki-dark-arts` | 「**黑暗**（Dark Arts）。…All Shrouded damage is increased by an additional 10%」 |

第二条同时是**真俗称**：玩家说「黑魔法」，语料是「黑暗（Dark Arts）」→ 归入 `colloquial`。

> ⚠️ **教训：扩充语料后必须复查 `gap` 标注。**
> 标注是"当时语料里没有"的快照 —— 语料变了它就**过时**了。
> 本次 `gap` 干净率看起来从 31.6% 掉到 26.3%，实际是**两条已经不该算 gap** 了。
> 复查后才是真实的 29.4%。

#### ⚠️ 同时暴露的语料质量问题

自动导入的块**正文是英文**，且清洗后有模板残渣：

```
[wiki-abyss] Abyss
    is a skill in Enshrouded.            ← 开头没有主语（模板被剥掉留下的）
    Description All Shrouded damage is increased by an additional 20%.
[wiki-quests-nursery-supplies] "Nursery Supplies"
    is a quest in Enshrouded, started by reading .   ← "reading ." 后面缺了东西
```

- **英文正文**：物品图鉴是我们自己整理的中文，wiki 自动导入的是英文原文。
  跨语言检索（bge-m3）能用，但**模型看到的是英文资料**。
- **模板残渣**：正是《知识库文档格式规范》4.3 节列为「反面教材」的那类问题。

> 结论：**自动导入适合"先有资料"，质量要靠后续人工整理。**
> 这也解释了为什么 `Item catalogs` 被刻意排除（清洗后基本是链接与表格）。

### ★ 近名污染是**系统性**的，不是个例

| 提问 | 期望 | 实际赢的 | 关系 |
|---|---|---|---|
| 还是不能召唤空荡独眼巨人 | `wiki-hollow-cyclops`（Boss） | `hollow-cyclops-trophy`（**战利品**） | 前缀相同 |
| 腐血是什么 | `rotblood`（腐血） | `corrosive-blood`（**腐蚀之血**） | 名字相似 |
| 城堡方块的获取方法 | `castle-block` | `castle-roof-block`（**屋顶方块**） | 前缀相同 |
| 珍珠母有什么用 | `mother-of-pearl` | 被 `pearl` 压到第 2 | 片段包含 |

**规律：具体物品块（`X战利品`/`X屋顶方块`）赢过通用页。**
现有 2,577 条物品块里大量是「A（B）」结构，短提问很容易撞上它们的片段。

### 另一类失败：短提问返回**空**

```

可以挤牛奶吗         → 0 命中（milk 就在库里）
```

**这和 `gap` 相反** —— gap 是"不该答却硬答"，这里是"该答却说没查到"。
两类都需要单独盯。

### ⚠️ 我自己标错的一条（已删）

`游牧高低 燃火荒原瘴气区 会走动的蘑菇怪` → 我标了 `wiki-mushroom-crab`，
但查正文发现该块写的是「Revelwood 森林」的蘑菇蟹，**地点与提问不符**，可能根本不是同一种生物。
→ 标注不可信，**删掉**。期望块写错会造成假红，假红几次就没人信这条测试了。

### 关于「通用中文名」风险的实测结论

批次 1 的 403 块里有 **65 块（16%）中文名 ≤3 字**（法师/猎人/铁匠/农夫/太阳/永恒…，
且「猎人」×7、「铁匠」×5 等**撞名**）。配置里警告过这类标题可能抬高 C 路误触发率。

**实测：这个风险没有以"劫持"的形式出现，反而相反 —— 这些通用页输给了具体物品块。**
（「空荡独眼巨人」输给战利品，而不是赢过它。）
所以现阶段不用急着改 `NameZhIndex`；但要**继续用黄金集盯住**，批次 2（Lore 264 页，英文专有名词标题）
才是这个风险真正该验的地方。

**导入**：264 页 → **364 块**，33.5 万字，0 失败。语料 **3,052 → 3,416 块**。
增量逻辑验证正确：`版本变过 264` —— 批次 1 的 373 页全部跳过 ✓

| 类别 | 批次 1 后 | 批次 2 后 |
|---|---|---|
| entity R@1 / R@5 | 70.0% / 90.0% | **70.0% / 90.0%** |
| colloquial R@1 / R@5 | 80% / 80% | **80% / 80%** |
| chitchat 干净率 | 93.3% | **93.3%** |
| gap 干净率 | 29.4% | **29.4%** |

**我点名的两个风险都没出现** ✓（英文专有名词标题**没有**抬高 C 路误触发 —— chitchat 干净率纹丝不动）。
**但也没有任何改善。**

### ⚠️ 修正：`Lore` 不是「世界观」，是「收集品笔记」

配置里原来的注释说「口语提问常见（『这游戏讲什么』）」——**实测是错的**。
`Lore` 的实际内容是游戏里的**收集品笔记/日志**：

```
明亮（A Bright Light In The Sky）   A Brother's Confession   A Cry For Help
被诅咒的（A Cursed Catch）         A Destroyed Roof         A Devious Performance
A Glimpse Of Eternity             A Scattered Legacy       ...
```

而且**里面没有任何**「力量/智力/属性/体质/敏捷」内容。**所以它没有触及最大的缺口簇。**

> 无退化的原因也清楚了：这些页大多**没有中文名**，标题保持英文，
> 反而不容易撞上中文提问的标题闸门。

## 〇·五、★ 真正的根因：**600 条词条没有中文名（18%）**

查完批次 2 之后，缺口词（法师 71 / 技能 44 / 属性 13 / 力量 13 / 智力 10 …）的根因终于清楚了：

**不是「库里没有内容」，是「库里有内容但没有中文名」。**

| 属性 | 块 id | 词条表的 zh |
|---|---|---|
| 力量 | `wiki-strength` | `Strength` ← 纯英文 |
| 智力 | `wiki-intelligence` | `Intelligence` |
| 体质 | `wiki-constitution` | `Constitution` |
| 敏捷 | `wiki-dexterity` | `Dexterity` |
| 耐力 | `wiki-endurance` | `Endurance` |
| 战斗机制 | `wiki-combat-mechanics` | `Combat Mechanics` |
| 制作 | `wiki-crafting` | `Crafting` |

```
600 / 3416 条词条的 zh 是纯 ASCII（=没有中文名），占 18%
样例：Absorb / Abyss / Airborne / Arcane Concentration / Barbarian / Bard / Bash / Battle Heal …
```

**这 600 条就是中文提问永远够不到的那部分。** B 路（关键词）靠「词条名出现在问句里」判定命中，
中文问句里永远不会出现 `Intelligence`。

### 而这个缺口是**代码里早就写明的**

> 实测 `Combat Mechanics` / `Crafting` / `Survival` 这类机制词条语料里没有译名，
> 就只能留英文（**那部分要靠别名表人工补**）。 —— `NameZhIndex` 类注释

**别名表就是词条表的 `zh` 列**（管理端「词条」面板 + `POST /terms/import` CSV），
而且导入**不会覆盖已有的中文名**（只在为空时补齐）。

### 但翻译源是缺的

`TRANSLATE-SPEC.md` 里写着「术语优先查 `server/data/kb/glossary/zh-en.tsv`」——
**这个文件在本仓库里不存在**（物品图鉴的中文名来自 `docs/gamedata/_source/*.json` 的 `zh` 字段，
而那些 JSON 只覆盖物品，不覆盖技能/机制/属性）。

### 所以下一步应该是**补中文名，而不是继续抓页**

按缺口频次优先，第一批只要 ~25 个词条就能覆盖最大的那一簇：

```
Strength→力量  Intelligence→智力  Constitution→体质  Dexterity→敏捷  Endurance→耐力
Crafting→制作  Combat Mechanics→战斗机制  Survival→生存  Shroud→瘴气  Death→死亡
Comfort→舒适度  Skill Points→技能点  ...
```

**比再抓 300 页便宜得多，而且直击缺口。**

## 一、怎么重跑

```bash
# 生产默认路径（含 cross-encoder 重排）
mvn test -Dqqbot.golden.rerank=on -Dtest=RetrievalGoldenTest

# 退化路径（关掉重排，用于对比"重排到底贡献了多少"）
mvn test -Dqqbot.golden.rerank=off -Dtest=RetrievalGoldenTest
```

- 需要 `.env` 里的 `SILICONFLOW_API_KEY`（**会产生 API 调用**，量很小）
- 用**生产库的副本**跑，**不碰真库**；跑完把逐条明细写到 `target/golden-detail.tsv`
- 没有生产库或没有黄金集时**自动跳过**（不让缺数据的机器构建失败）
- ⚠️ 输出用平台编码。在中文 Windows 控制台直接看没问题；在 CI（POSIX/ASCII）里中文会乱码，
  但**表格里的数字和类别名是 ASCII**，照样能读

## 四、★ 这条基线的盲区（必须先知道）

**第一次测量时黄金集只有 42 条，而 `colloquial` 只有 2 条。现在已经补到 61 条 / 3 条**，
但**盲区没有消失，只是缩小了**：

```
entity        15 条
colloquial     3 条   ← 仍然很少
gap           19 条
chitchat      15 条
descriptive    9 条   （未标注，不参与打分）
```

### 为什么 `colloquial` 长不大 —— 这是个结论，不是偷懒

从 **125 个真实缺口词 + 100 条真实提问**里筛，能**干净配对**的真俗称只有 **1 条**。

原因（见 `docs/md/黄金集候选-2026-10-04.md`）：**群友问的是「系统」，语料是「物品」。**

```
法师 71  技能 44  箱子 37  技能点 28  装备 26  法杖 21  武器 18
任务 17  戒指 17  地图 14  力量 13  属性 13  魔法 12  智力 10 ...
```

这些词 93% 不在库里 —— **不是因为页数不够，是因为语料只覆盖「东西」不覆盖「系统」。**
所以这些真实提问**只能归到 `gap`，不能归到 `colloquial`**。

### 后果（比第一次更清楚）

1. `colloquial` 仍然只有 3 条 → `R@1` 一条错就掉到 66.7%，**门槛 75% → 假红**。
2. **但更重要的结论是**：你最初的抱怨「口语提问答得很差」，
   **根因不是俗称不匹配（那种只有 2+1 例），而是群友问的系统级问题我们根本没有资料** ——
   它们变成 `gap`（19 条里只有 6 条返回空），机器人**硬凑答案**。
3. **所以正确的顺序是交替的**：先把能配对的加进去（已做），
   再扩充系统级语料（技能/属性/任务/地图），然后把新变「可回答」的提问从 `gap` 转成 `colloquial`。

## 五、怎么读这张表

| 类别 | 它在问什么 | 现状 |

| **entity** | 问一个**语料里确实有的**东西，能不能排到第 1 | ✅ 91.7%，R@5 100% |
