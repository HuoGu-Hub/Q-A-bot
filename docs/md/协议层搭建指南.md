# 协议层搭建指南：用 Docker Compose 跑起 NapCat

> 这一层只有一个容器。跑通它 = 你的机器上有一台"能收发 QQ 消息的翻译机"。
> 业务层（Java 工程）之后再说，**这一层没通之前不要碰业务代码**。

---

## 0. 这一层到底在搭什么

```
   ┌─────────────────────────────────────────────┐
   │  协议层（本文要搭的，就一个容器）              │
   │                                             │
   │   NapCat                                    │
   │   · 登录你的 QQ 号                           │
   │   · 把 QQ 私有协议翻译成标准 JSON（OneBot 11） │
   │   · 对外开两个口：                            │
   │       3000 → HTTP 接口（让别人调它发消息）     │
   │       3001 → WebSocket（双向实时收发）        │
   │       6099 → WebUI 管理后台（只给你自己用）    │
   └─────────────────────────────────────────────┘
              ↑ 之后你的 Java 工程就接在这两个口上
   ┌─────────────────────────────────────────────┐
   │  业务层（下一阶段，现在不碰）                  │
   └─────────────────────────────────────────────┘
```

---

## 1. 前置：宿主机要有 Docker

先确认装好了：

```bash
docker --version
docker compose version
```

两条命令都能输出版本号就 OK。

- **Windows**：装 Docker Desktop（安装时会自动带上 compose）
- **Linux**：`apt install docker.io docker-compose-plugin` 或按官方文档装 Docker CE
- **群晖/威联通**：套件中心装 Container Manager，自带 compose

> ⚠️ 注意：**Docker 要装在宿主机上**。你现在做开发的那台机器。

---

## 2. 三步把镜像拉下来并启动

我已经把编排文件写好了，在 `deploy/docker-compose.yml`。进去执行：

```bash
cd deploy

# 第 1 步：下载镜像（就是你要的"用 compose 下载"）
docker compose pull

# 第 2 步：后台启动
docker compose up -d

# 第 3 步：看日志，等它启动完
docker compose logs -f
```

**看到日志里出现 WebUI 的地址和 Token 就说明起来了。** 类似这样：

```
[WebUI] WebUI Token: a1b2c3d4e5f6
[WebUI] WebUI URL: http://127.0.0.1:6099/webui?token=a1b2c3d4e5f6
```

**把这个 Token 记下来**，登录管理后台要用。Token 是随机的，每次重建容器可能会变。
如果日志滚过去了没看清，用 `docker compose logs napcat | grep -i token` 再捞一次。

> 想看它在不在跑：`docker compose ps`，STATUS 显示 `Up` 就对了。

---

## 3. 登录 QQ（扫码）

1. 浏览器打开日志里那个地址：`http://127.0.0.1:6099/webui?token=你的Token`
2. 用**专门注册的机器人小号**扫码登录

> 🔴 **重要**：这个 QQ 号**不能同时**在手机 QQ / 电脑 QQ 上登录，会互相踢下线。
> 一定要用一个单独的号，别用你日常在用的号。

登录成功后，WebUI 首页会显示这个号的昵称和 QQ 号——**这就意味着协议层已经"活着"了**。

---

## 4. 开启 OneBot 的接口（关键一步，很多人卡在这）

刚装好的 NapCat **默认什么接口都不开**——五个网络适配器全是空数组。
症状：端口「能连上但没有任何响应」（Empty reply from server）。

### 4.1 先分清两个方向

| 方向 | 建什么 | 作用 |
|---|---|---|
| 业务层 → NapCat | **HTTP服务器** | 你的程序调它**发**消息 |
| NapCat → 业务层 | **HTTP客户端**（HTTP上报） | 它把 QQ 消息**推**给你的程序 |

只做定时播报 → 只建第一个。要收消息再回复 → 两个都要。

### 4.2 建 HTTP服务器

WebUI → **网络配置** → 点左上角 **＋** → 选 **HTTP服务器**：

| 字段 | 填什么 | 说明 |
|---|---|---|
| 启用 | 打开 | 「保存后启用此配置」 |
| 名称 | 随便，如 `http-server` | 保存后不可修改 |
| **Host** | **`0.0.0.0`** | ⚠️ 重点，**不要**用默认的 `127.0.0.1` |
| Port | `3000` | 要和 docker-compose 里映射的端口一致 |
| 启用CORS | 保持打开 | |
| 启用Websocket | 建议打开 | 打开后可用同一端口连 WebSocket |
| 消息格式 | `Array` | 比 String 好处理 |
| Token | **默认已自动生成 16 位随机串，不要删** | 复制下来，业务层要用 |
| 开启Debug | 先不开 | |

> ### ⚠️ 为什么 Host 必须是 `0.0.0.0`
> Docker 的端口映射把连接转发到**容器的网卡 IP**，而不是容器的 `127.0.0.1`。
> - 监听 `127.0.0.1` → 只接受容器内部的访问 → 从宿主机转发进来被拒
> - 监听 `0.0.0.0` → 接受所有网卡 → 转发正常
>
> 另外 NapCat 有个安全机制：**Token 留空且 Host 不是 `127.0.0.1` 时，保存会弹窗并强制把 Host 改回 `127.0.0.1`**。所以 Token 千万别删。

### 4.3 建 HTTP客户端（要接收消息才需要）

| 字段 | 填什么 |
|---|---|
| 启用 | 打开 |
| 名称 | 随便 |
| URL | **`http://host.docker.internal:8080/onebot/event`** |
| 消息格式 | `Array` |
| reportSelfMessage | **保持关闭** |
| Token | 和业务层约定的一致 |

> ### ⚠️ 容器里不能用 `127.0.0.1` 访问宿主机
> `127.0.0.1` / `localhost` 在容器内指的是**容器自己**，不是宿主机。
> Docker Desktop（Windows/Mac）用 `host.docker.internal` 代替；Linux 上需要给容器加
> `extra_hosts: ["host.docker.internal:host-gateway"]`。
> 别忘了**带上路径** `/onebot/event`。

> ### ⚠️ 业务层也必须监听 `0.0.0.0`
> 从容器发来的连接源地址是 Docker 网桥网关，不是 127.0.0.1。
> Spring Boot 默认就监听所有网卡——**别去配 `server.address: 127.0.0.1`**，否则照样连不上。

> ### 💡 更省心的替代方案
> 把方向反过来：**让业务层主动连 NapCat**。
> HTTP服务器勾上「启用Websocket」后，业务层直接连 `ws://127.0.0.1:3000` 收事件、
> 用 HTTP 调同一个端口发消息。这样**完全不需要 NapCat 反连业务层**，也就没有
> `host.docker.internal` 的麻烦——代价是业务层要写 WebSocket 客户端。

> 补充：网络配置**保存后即时生效**（源码里 `reload()` 会自动重启适配器），不用重启容器。

## 5. 验证：协议层真的通了

这是整篇最重要的一步——**不要靠"感觉"判断，直接调一次接口**：

```bash
# 把 TOKEN 换成你上面设的 Access Token
TOKEN=你的AccessToken

curl -s http://127.0.0.1:3000/get_login_info \
  -H "Authorization: Bearer $TOKEN"
```

预期返回：

```json
{
  "status": "ok",
  "retcode": 0,
  "data": {
    "user_id": 123456789,
    "nickname": "你的机器人昵称"
  }
}
```

**看到 `status: ok` 并且 `user_id` 是你的机器人 QQ 号 —— 协议层就算搭好了。**

如果返回 403 / 401，说明 Token 不对；如果连不上，说明 HTTP 服务端没开或端口没映射。

## 6. 安全清单（照着检查一遍）

- [ ] WebUI 的 6099 端口**只监听 127.0.0.1**（compose 里已经这么配了），不要暴露到公网
- [ ] OneBot 的 Access Token 是**随机长串**，不是 `123456`
- [ ] `reportSelfMessage` 关闭
- [ ] 用的是**专用小号**，不是日常号
- [ ] 如果是云服务器，安全组里**不要**对公网开放 3000 / 3001 / 6099

> 如果 Docker 跑在远程服务器上，WebUI 用 SSH 隧道访问，别直接开端口：
> `ssh -L 6099:127.0.0.1:6099 user@服务器IP`，然后浏览器访问本机的 6099。

## 7. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `docker compose pull` 卡住 / 超时 | 国内拉 Docker Hub 慢 | 给 Docker 配镜像加速器，或用代理 |
| WebUI 打不开 | 端口没映射 / 容器没起来 | `docker compose ps` 看状态；`docker compose logs` 看报错 |
| 登录后很快掉线 | 同一个号在别处登录了 | 退出手机/电脑 QQ 上的这个号 |
| 扫完码没反应 | 网络受限或风控 | 换个网络环境重试；确认是全新小号 |
| `./data` 目录文件全是 root | UID/GID 没设 | 在 `deploy/.env` 里填 `id -u` / `id -g` 的结果后重启 |
| 重启容器又要重新扫码 | 没挂载 `./data/qq` | compose 里已经挂好了，确认目录存在且可写 |
| curl 调接口 401/403 | Token 不匹配 | WebUI 里的 Access Token 和 curl 里填的要一致 |
| curl 连不上 3000 | HTTP 服务端没开 | 回到第 4 步，确认已保存并生效 |

**更新 NapCat 到最新版**：

```bash
docker compose pull && docker compose up -d
```

## 8. 这一层搭好之后，你手上就有了什么

- 一个正在跑的 NapCat 容器
- 一个 HTTP 接口：`http://127.0.0.1:3000/<动作名>`，带上 Token 就能调
- 一个 WebSocket 入口：`ws://127.0.0.1:3001`
- 一个挂载在 `deploy/data/` 下的持久化目录（登录态和配置都在这）

**接下来（下一阶段）才轮到业务层**：

1. 建 Spring Boot 工程
2. 在 NapCat 的"HTTP 上报"里填上你程序的地址，让它把消息推过来
3. 收到消息 → 回一句固定文本（先跑通管道）
4. 管道通了，再把大模型接进去

> 顺序别乱：**先把管道接通，再考虑管道里流什么。**
