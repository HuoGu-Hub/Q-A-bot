# 公网部署指南

> 面向「公开站给群友看 + 管理后台只给自己」的部署。**上服务器前请通读第九节的风险清单。**

---

## 一、部署形态

```text
                    公网
                      │
              ┌───────┴───────┐
              ▼               ▼
   www.example.com    admin.example.com
   （公开站）          （管理后台）
              │               │
              └───────┬───────┘
                      ▼
                  Nginx :443
              ┌───────┴────────┐
              │  限流 / IP 白名单 │
              └───────┬────────┘
                      ▼
              Spring Boot :8080
              ┌───────┴────────┐
              │  /api/public/** │ 公开只读
              │  /admin/api/**  │ 需会话
              └────────────────┘
                      ▼
              data/qa/qa.sqlite
              data/kb/**（语料与索引）
```

---

## 二、服务器要求

| 项 | 最低 | 说明 |
|---|---|---|
| 内存 | **2 GB** | 索引常驻约 16 MB，Spring Boot 约占 400 MB |
| 磁盘 | 20 GB | 语料 + 索引约 20 MB，SQLite 长期几十 MB |
| 出网 | 需要 | NapCat 连 QQ、向量模型 API |
| 系统 | Debian/Ubuntu | 本指南以 Debian 13 为例 |

## 四、配置

### 4.1 `.env`

```bash
cd /opt/qqbot
cp .env.example .env
chmod 600 .env      # ★ 里面有密钥，权限收紧
vi .env
```

必填项：

| 变量 | 说明 |
|---|---|
| `ONEBOT_TOKEN` | 与 NapCat 里配置的一致 |
| `OPENCODE_GO_API_KEY` | 对话模型 |
| `SILICONFLOW_API_KEY` | **向量模型（检索用，别漏）** |
| `ADMIN_PASSWORD` | **管理后台密码。不设 = 后台整个 503** |
| `NAPCAT_MAC` | NapCat 设备指纹 |

### 4.2 协议层（NapCat）

按 `deploy/docker-compose.yml` 起容器。**关键：端口只绑本机**，不要暴露到公网：

```yaml
ports:
  - "127.0.0.1:3000:3000"    # ← 必须是 127.0.0.1，不是 0.0.0.0
```

## 五、构建与启动

### 5.1 构建前端

```bash
./scripts/build-web.sh
```

产物会同步到 `server/web-dist/`。

### 5.2 构建并打包后端

```bash
cd server
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
mvn -q clean package -DskipTests
```

### 5.3 systemd 服务

> ⚠️ **`WorkingDirectory` 决定了所有数据放在哪**，不是 jar 放在哪。
> `app.qa.db`、`app.kb.dir`、`app.site.carousel.dir`（首页轮播图片）、图片缓存、临时图片、日志
> —— 全是**相对路径**，基准就是进程的工作目录。上面写成 `/opt/qqbot/server`，
> 所以数据都在 `/opt/qqbot/server/data/` 下。
>
> 这个搞错的后果**不是报错**，而是它在新位置**现建一套空库空语料** —— 看起来就像数据全丢了。
> 所以：改这里的路径 = 换了一整套数据，迁移时要连 `data/` 一起搬。
>
> 启动日志里会把这些路径的绝对形式打出来（搜 `[路径]`），核对一下最省事：
> ```
> [路径] 进程工作目录：/opt/qqbot/server
> [路径] 问答库（统计 / 词条表 / 分类 / 文案 / 轮播清单）：/opt/qqbot/server/data/qa/qqbot.sqlite
> [路径] 首页轮播图片：/opt/qqbot/server/data/site-images
> ```
>
> 想彻底和"当前在哪个目录"脱钩，就把这几个路径**写成绝对路径**放进 `EnvironmentFile`（实测有效）：
> ```bash
> # 取消注释、填绝对路径；⚠️ 别写成 KEY= 空值（空值 ≠ 不写，会解析成空路径）
> APP_QA_DB=/opt/qqbot/data/qqbot.sqlite
> APP_KB_DIR=/opt/qqbot/data/kb
> APP_SITE_CAROUSEL_DIR=/opt/qqbot/data/site-images
> ```
> （变量名 = 配置项去掉短横线后大写：`app.media.kb-images.dir` → `APP_MEDIA_KBIMAGES_DIR`。）
> 也可以在 ExecStart 后面直接加 `--app.qa.db=/opt/qqbot/data/qqbot.sqlite` 这种参数，效果一样。
> 注意换了位置要同步改下面的 `ReadWritePaths`，否则 `ProtectSystem=strict` 会让它写不进去。

```bash
sudo tee /etc/systemd/system/qqbot.service > /dev/null <<'EOF'
[Unit]
Description=QQ Bot (飘雪喵)
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
User=qqbot
WorkingDirectory=/opt/qqbot/server
EnvironmentFile=/opt/qqbot/.env
ExecStart=/usr/bin/java -Xmx512m -Dfile.encoding=UTF-8 -jar /opt/qqbot/server/target/qqbot-server-0.0.1-SNAPSHOT.jar
Restart=always
RestartSec=10

# 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/qqbot/server/data

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now qqbot
sudo systemctl status qqbot
```

> `-Xmx512m` 是刻意的：2 GB 机器上给系统和其他进程留足余量。

## 六、Nginx

### 6.1 放配置

```bash
sudo cp deploy/nginx/qqbot.conf /etc/nginx/sites-available/qqbot.conf
sudo ln -s /etc/nginx/sites-available/qqbot.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
```

**改两个地方**：

1. `server_name` → 你的域名
2. `allow 203.0.113.42;` → **你自己的 IP**（后台白名单）

### 6.2 HTTPS

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d www.example.com -d admin.example.com
```

### 6.3 生效

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 八、日常运维

### 改系统提示词（不用重新打包）

系统提示词就是仓库根目录的 **`AGENTS.md`**。加载优先级：

```text
① 外部文件  ./AGENTS.md → ../AGENTS.md → ../../AGENTS.md   ← 优先
② classpath 内置副本（构建时从根目录复制进 jar）           ← 回退
③ 都没有 → 兜底话术（日志打 ERROR 提醒）
```

上线后想改人格/规则，**直接在服务器上改 `AGENTS.md` 然后重启即可**：

```bash
vi /opt/qqbot/AGENTS.md
sudo systemctl restart qqbot
sudo journalctl -u qqbot | grep "已加载系统提示词"
```

日志能一眼看出读的是哪份：

```text
[LLM] 已加载系统提示词：file:../AGENTS.md（外部文件，改完重启即生效）（3256 字）
```

> **为什么用 `AGENTS.md` 这个名字**：它是 Agent 生态的通行约定，
> 将来迁移到正式 Agent 框架（Claude Code / Cursor 等）可以直接复用提示词，不用重写。

### 看日志

```bash
sudo journalctl -u qqbot -f
```

### 备份

**要备份的就两样**：

```bash
# ① 一个 sqlite 装下了全部"人工成果"：
#    问答统计、词条表（中文名 + 核对状态）、分类映射、页面文案、轮播清单
sqlite3 /opt/qqbot/server/data/qa/qa.sqlite ".backup /backup/qa-$(date +%F).sqlite"

# ② 首页轮播的图片（管理端上传的，丢了只能重新找图）
cp -r /opt/qqbot/server/data/site-images /backup/
```

> ⚠️ **术语表已经不在 TSV 里了**（2026-09-27 起搬进 ① 那个 sqlite 的 `kb_term` 表）。
> `data/kb/glossary/zh-en.tsv` 现在只是"导入导出用的中间格式"，**不用再单独备份**。
>
> 语料和索引**不用备份** —— 可以随时重建（`from-raw` 模式 18 秒；
> 但**改了清洗规则就必须连向量一起重建**，约 4 分钟、按 embedding 计费，见下一节）。
>
> 首页轮播的图片走**管理端上传**（`页面信息 → 首页轮播`），
> 存放目录是 `app.site.carousel.dir`（默认 `./data/site-images`）。
> 上传时 nginx 和 Spring 各有一道体积上限，见 `deploy/nginx/qqbot.conf` 里的 `client_max_body_size`。

### 重建语料（游戏更新后）

```bash
cd /opt/qqbot/server
java -jar target/qqbot-server-*.jar \
  --app.kb.build.enabled=true --spring.main.web-application-type=none
java -jar target/qqbot-server-*.jar \
  --app.kb.index.enabled=true --spring.main.web-application-type=none
```

### 更新部署

```bash
cd /opt/qqbot
git pull
./scripts/build-web.sh
cd server && mvn -q clean package -DskipTests
sudo systemctl restart qqbot
```

## 九、⚠️ 公网部署风险清单

| # | 风险 | 应对 |
|---|---|---|
| **R1** | **管理后台被公网扫到** | Nginx 独立域名 + **IP 白名单**；公开站域名下 `/admin/` 直接 404 |
| **R2** | **密码被爆破** | 登录接口 Nginx 限流（5 次/分）；密码用长随机串 |
| **R3** | **公开接口被刷爆** | 应用层 60 次/分 + Nginx 层限流，双层 |
| **R4** | **向量模型额度被烧** | 检索走公开接口 → 已限流；必要时临时关 `app.kb.enabled` |
| **R5** | **隐私泄露** | 公开接口用独立 DTO，**绝不复用管理接口**；上线后抓包复查 |
| **R6** | **服务器 IP 暴露** | 用 Cloudflare 之类的 CDN 挡在前面（可选但推荐） |
| **R7** | **QQ 账号被风控** | 见 `docs/NapCat登录丢失排查与解决.md` |
| **R8** | **动态 IP 导致白名单失效** | 改用 VPN 进内网，或把后台路径改成随机串 |

### 上线后必做的一次复查

```bash
# 公开接口返回体里不能出现任何隐私字段
curl -s https://www.example.com/api/public/kb/search?q=Scrap \
  | grep -oE '"(userId|groupId|user_id|group_id|bestCosine|qq)"' | sort -u
# 期望：无输出
```

## 十、出问题怎么办

| 现象 | 先查 |
|---|---|
| 机器人不回复 | `journalctl -u qqbot` 找「连不上 NapCat」 |
| 公开站 502 | `systemctl status qqbot`；Nginx `error.log` |
| 后台打不开 | 是不是你的 IP 不在白名单？先临时加 `allow` 试 |
| 检索变慢 | 向量模型 API 是否正常；看日志里的「A 路失败」 |
| 磁盘涨得快 | `data/tmp-images` 清理是否在跑；SQLite 的 WAL 大小 |
