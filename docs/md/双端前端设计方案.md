# 双端前端设计方案（管理后台 + 公开站）

> 状态：**待评审** ｜ 2026-09-22
> 目标：把现有的静态页面升级为 Vue 工程化的**两个端**，主题贴合《雾锁王国》世界观

---

## 一、结论先行

| 决策 | 结论 |
|---|---|
| 前端位置 | `web/`，**与 `server/` 同级** |
| 技术栈 | Vue 3 + Vite + TypeScript（不用 Nuxt —— 不需要 SSR） |
| 端 | **两个**：`admin`（给你看）+ `public`（面向群友） |
| 主题 | **按游戏本体调性**，不按泛中世纪风（依据见第四节） |
| 大屏 | 并入 `admin`，**60 秒自动刷新** |
| 数据大屏定位 | ⚠️ 见下方说明 |

### ⚠️ 必须先说清楚："数据大屏"和"面向用户"是两回事

你后来说"数据大屏跟项目不匹配，我需要面对用户的" —— 这个判断对，但**它们不是同一层的东西**：

| | 数据大屏 | 面向用户 |
|---|---|---|
| 给谁看 | 你（演示/挂机） | 群友 |
| 内容 | 命中率、余弦分布 | 问过什么、资料库 |
| 鉴权 | 要密码 | **不能要密码** |

**所以不是"用大屏替代用户端"，而是：**
- **管理后台**（`admin`）：保留大屏 + 统计 + 标注 + 术语表，**仍然要密码**
- **公开站**（`public`）：全新的、面向群友的、只读的 —— 这才是"面对用户"

## 二、公开站到底给群友看什么

这是设计的核心问题。三个候选：

| 方案 | 内容 | 评价 |
|---|---|---|
| A. 问答广场 | 大家问过的问题 + 机器人的回答（脱敏） | ⚠️ 有隐私风险：群友可能不想被围观 |
| B. **游戏资料库** | 把知识库（3,649 页语料）做成可浏览的图鉴 | ✅ **推荐**：内容本身是公开 wiki，无隐私问题 |
| C. 群助手主页 | 介绍功能 + 排行榜（谁问得最多） | ✅ 可作 A/B 的补充 |

**推荐：B 为主，C 为辅，A 谨慎做。**

理由：

1. **B 的内容零隐私风险** —— 就是 wiki 语料，本来就公开
2. **B 对群友真有价值** —— "废料杯怎么合成"直接在网页上搜，比在群里问还快
3. **A 有真实风险** —— 群友的提问原文（含 QQ 号）被公开展示，即使脱敏也可能被认出来（"这不是我昨天问的吗"）

**如果要做 A**，必须：只展示**人工标记为 `good`** 的问答、**去掉 QQ 号**、**去掉时间**、且**默认关闭**。

## 三、架构与安全

```text
┌───────────────── 浏览器 ─────────────────┐
│  www.example.com        admin.example.com │
│  （公开站）              （管理后台）      │
└──────────┬────────────────────┬───────────┘
           │  静态资源           │  静态资源
           ▼                     ▼
┌──────────────────────────────────────────────┐
│              Nginx / 反向代理                 │
│  /            → web/dist/public               │
│  /admin/      → web/dist/admin  + IP 白名单   │
│  /api/**      → server:8080   （公开只读）    │
│  /admin/api/**→ server:8080   （需登录）      │
└──────────────────┬───────────────────────────┘
                   ▼
┌──────────────────────────────────────────────┐
│         Spring Boot（server/，不变）          │
│  /api/**        新增：公开只读接口            │
│  /admin/api/**  已有：管理接口（要密码）      │
└──────────────────────────────────────────────┘
```

### ⚠️ 核心安全矛盾：公开站会让后台一起暴露

现在 `server.address: 0.0.0.0`，端口一旦对外，**管理后台和公开站一起暴露**。

**三道防线**（缺一不可）：

| # | 措施 | 说明 |
|---|---|---|
| 1 | **路径隔离** | 公开接口放 `/api/**`，管理接口留 `/admin/api/**`，前者**只读**、**不返回任何隐私字段** |
| 2 | **管理后台入口保护** | Nginx 层对 `/admin` 做 **IP 白名单**，或换成随机路径；密码是最后一道，不是第一道 |
| 3 | **公开接口限流** | 按 IP 限流（如 60 次/分钟），防止被刷 |

> **绝对不能做的**：让 `/api/**` 复用 `AdminController` 的方法。
> 公开接口必须**另写**，只 SELECT 需要公开的列 —— 而不是把管理接口"去掉鉴权"。

### 数据边界

| 字段 | 公开站 | 管理后台 |
|---|---|---|
| 问题原文 | 仅 `good` 且脱敏 | ✅ 全量 |
| 回答原文 | 仅 `good` | ✅ 全量 |
| QQ 号 / 群号 | ❌ **绝不返回** | ✅ |
| 检索指标（余弦/来源） | ❌ | ✅ |
| 知识库语料 | ✅ **全量**（本来就是公开 wiki） | ✅ |

## 四、视觉设计：不做"泛中世纪"，做"雾锁王国"

### 4.1 依据：从官方美术素材提取的真实配色

我下载了 wiki 的官方图（Flame Altar、Embervale、站点 logo），用 PNG 解码做了色彩量化。**实测结果**：

```text
合并主色 Top 12：
  #000000  28.8%   ████████████████████████████
  #202030  11.4%   ███████████        ← 雾霭蓝灰
  #707070   9.5%   █████████          ← 石材灰
  #606060   8.6%   ████████
  #101000   6.5%   ██████             ← 暗橄榄
  #202020   6.4%   ██████
  #101020   6.4%   ██████             ← 深夜蓝
  #404010   4.3%   ████               ← 土黄/苔藓
  #303010   4.3%   ████
```

**结论：这个游戏的视觉是"暗底 + 蓝灰雾 + 苔藓土黄"，不是金碧辉煌的中世纪。**

所以设计语言定为 **"雾中灵火"**：
- **底**：近乎黑的深蓝灰（不是纯黑，要留住阴影层次）
- **主强调**：灵火橙（游戏中 Flame Altar 的火光 —— 唯一的高饱和暖色，用在最需要关注的地方）
- **辅**：雾霭蓝灰、苔藓绿、石灰白
- **质感**：石材/布料的粗糙感，靠**细微噪点纹理**和**内阴影**，不靠花哨渐变

### 4.2 设计令牌（Design Tokens）

```css
:root {
  /* —— 背景层次（由深到浅，模拟洞穴 → 地面 → 建筑内部）—— */
  --bg-abyss:    #0c0e12;   /* 最深：页面底 */
  --bg-shroud:   #141922;   /* 雾层：卡片底 */
  --bg-stone:    #1c222c;   /* 石材：抬升面 */
  --bg-raised:   #252c38;   /* 最高层：弹窗/悬停 */

  /* —— 灵火（唯一高饱和暖色，克制使用）—— */
  --flame-bright: #ffc46b;  /* 火心 */
  --flame:        #e8a04c;  /* 主强调（按钮/高亮/图标） */
  --flame-deep:   #b0702c;  /* 火底 */
  --flame-glow:   rgba(232,160,76,.28);  /* 光晕 */

  /* —— 自然色（语义色）—— */
  --moss:        #6b8f5e;   /* 成功 / 检索命中 */
  --moss-dim:    #3f5638;
  --rust:        #b5533f;   /* 失败 / 未命中 */
  --mist:        #7b8aa0;   /* 中性蓝灰 / 次要文字 */
  --amber-warn:  #c9a227;   /* 警告 */

  /* —— 文字 —— */
  --ink:         #e6e2d8;   /* 石灰白：正文 */
  --ink-dim:     #a8b0bd;   /* 次要 */
  --ink-faint:   #6b7482;   /* 禁用 / 占位 */

  /* —— 线条与描边 —— */
  --line:        #2c3440;
  --line-strong: #3d4756;
  --copper:      #8a6a3f;   /* 暗铜：装饰描边 */

  /* —— 圆角（偏硬朗，石材感，不用全圆）—— */
  --r-sm: 3px;  --r-md: 6px;  --r-lg: 10px;

  /* —— 阴影（暗色主题靠"暗得更深"而不是"投影"）—— */
  --shadow-inset: inset 0 1px 0 rgba(255,255,255,.04);
  --shadow-lift:  0 8px 24px rgba(0,0,0,.5);

  /* —— 字体 —— */
  --font-title: "Noto Serif SC", "Songti SC", Georgia, serif;  /* 石碑/古籍感 */
  --font-body:  "Noto Sans SC", -apple-system, "Segoe UI", sans-serif;
  --font-mono:  "JetBrains Mono", ui-monospace, monospace;     /* 数字/代码 */
}
```

> **字体说明**：标题用**衬线体**（石碑、古卷感），正文用**无衬线**（可读性优先）。
> 不做花体字 —— 群友要能一眼看清答案，风格不能牺牲功能。

### 4.3 质感细节（"游戏感"来自这里）

不靠贴图，靠 CSS：

| 手法 | 实现 | 效果 |
|---|---|---|
| 细微噪点 | SVG 滤镜 `feTurbulence` 做 2% 不透明叠加 | 石材/布料的粗糙感 |
| 灵火光晕 | `box-shadow` + radial-gradient | 关键元素的"火光感" |
| 描边双线 | `border` + `outline` 错开 1px | 金属镶嵌感 |
| 角落装饰 | ::before/::after 画小三角 | 面板四角 |
| 标题分隔 | 渐变横线（中间亮两端淡） | 古籍章节感 |

### 4.4 明暗模式

**只做深色。** 理由：

1. 游戏本身就是暗色调，浅色版会完全不像
2. 群友大多在手机上深夜看 —— 深色更合适
3. 少一套配色 = 少一半维护成本

## 七、前端工程结构

```text
web/                          ← 与 server/ 同级
├─ package.json
├─ vite.config.ts             多页构建：admin + public 两个入口
├─ tsconfig.json
├─ index.html                 public 入口
├─ admin.html                 admin 入口
└─ src/
   ├─ shared/                 两端共用
   │  ├─ api/                 API 客户端（fetch 封装 + 类型）
   │  ├─ types/               后端返回的 TS 类型
   │  └─ ui/                  通用组件（按钮/卡片/标签）
   ├─ theme/
   │  ├─ tokens.css           第四节的设计令牌
   │  ├─ base.css             重置 + 排版
   │  └─ texture.css          噪点/光晕/描边等质感
   ├─ public/                 公开站
   │  ├─ main.ts
   │  ├─ App.vue
   │  └─ views/               Home / Library / Entry / About
   └─ admin/                  管理后台
      ├─ main.ts
      ├─ App.vue
      └─ views/               Login / Screen / Dashboard / Records / Glossary
```

**构建产物**：`web/dist/public` 与 `web/dist/admin`，由 Nginx 或 Spring Boot 静态目录提供。

> 开发期 `vite dev` 代理 `/api` 与 `/admin/api` 到 `localhost:8080`，不跨域。

## 八、实施计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| **F1** 工程骨架 | `web/` 初始化、Vite 多入口、主题令牌、共享组件 | `pnpm dev` 能起来；令牌在两端生效 |
| **F2** 公开站 | 首页 + 资料库检索 + 词条页 + 关于 | 手机浏览器可浏览；**无任何隐私字段** |
| **F3** 后端公开接口 | `/api/public/**`（新写，不碰管理接口） | 抓包确认返回体里没有 QQ 号/群号 |
| **F4** 管理后台迁移 | 登录/看板/记录/术语表 迁到 Vue | 功能与现有静态页**完全等价** |

**F1~F3 是"能给别人看"的最小闭环。**

### 真跑才暴露的 5 个问题

| # | 问题 | 根因 | 处理 |
|---|---|---|---|
| 1 | pnpm 装不上 | 全局 store 在 `~/.local`，沙箱不可写 | store 挪到 `.toolchain/pnpm-store` |
| 2 | **`store-dir` 配置不生效** | pnpm 10+ **不再读 `.npmrc`**，只认命令行参数 | 脚本改用 `--store-dir` 传绝对路径 |
| 3 | `/admin.html` 被过滤器挡 | 把"前端壳子"和"数据接口"混为一谈 | 壳子放行（不含数据） |
| 4 | **`/admin/login` 302 死循环** | 重定向目标还是旧的 `login.html`（已归档） | 改为前端路由 `/admin/login` |
| 5 | 兜底路由吃掉接口 | 通配 `/{path}` 把 `/api/**` 也吃了 | 依赖 Spring"更具体映射优先"+ 验证 |

> 第 2、4 两条都是**只有真跑才会发现**的：
> 前者是配置方式随版本变了，后者是重构后遗留的旧路径引用。
> 单测和类型检查都覆盖不到。

## 九、风险

| # | 风险 | 应对 |
|---|---|---|
| **R1** | **公开站带出管理后台** | 路径隔离 + 新写公开接口 + Nginx 层保护后台入口 |
| **R2** | **问答广场泄露隐私** | 默认关闭；开启也仅 `good` + 脱敏 |
| **R3** | 前端工程化后失去"零依赖"的轻便 | 构建产物仍是静态文件，部署照旧；只在**开发期**需要 Node |
| **R4** | 主题做得太花影响易读性 | 花哨只用在**装饰层**；正文对比度必须达标（≥4.5:1） |
| **R5** | 移动端适配 | 公开站优先移动端（群友都用手机）；后台优先桌面 |
| **R6** | 重构期间现有后台不可用 | 保持旧静态页可用，**并行验证后再切换** |

### 关于部署位置（问题 2）

| 场景 | 安全压力 | 方案 |

| 只在内网/自己看 | 低 | 密码 + 路径隔离够用 |

| 群友访问 + 你懒得管 | 高 | 建议只公开**资料库**，问答数据完全不公开 |
