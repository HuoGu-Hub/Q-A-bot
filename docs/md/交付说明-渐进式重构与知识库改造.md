## 2. 运维命令（开关名已与代码核对）

### 2.1 落语料：地图 → 地点 → 任务/机制

**顺序有依赖**：地点语料由地图 marker 派生，所以必须先同步地图。

```bash
# ① 地图同步（增量：只拉 revid 变过的页）
mvn spring-boot:run -Dspring-boot.run.arguments="\
--app.kb.map-sync.sync-on-start=true --spring.main.web-application-type=none"

# ② 地点语料派生（83 条：区域/POI/具名地点/NPC）
mvn spring-boot:run -Dspring-boot.run.arguments="\
--app.kb.location-corpus.build-on-start=true --spring.main.web-application-type=none"

# ③ 任务 + 机制语料导入（`Quests/` 前缀 + Gameplay/Bosses/Craftspeople 分类）
mvn spring-boot:run -Dspring-boot.run.arguments="\
--app.kb.wiki-import.import-on-start=true --spring.main.web-application-type=none"
```

### 2.2 先看数量、不写库（dry-run）

把 `--app.kb.xxx.dry-run=true` 加进去即可，三个入口都支持：

```bash
--app.kb.map-sync.dry-run=true
--app.kb.location-corpus.dry-run=true
--app.kb.wiki-import.dry-run=true
```

### 2.3 回滚（**每批语料都能单独清掉**）

```bash
# 清掉全部派生地点块（按 docId = 地图·地点）
mvn spring-boot:run -Dspring-boot.run.arguments="\
--app.kb.location-corpus.build-on-start=true --app.kb.location-corpus.purge=true \
--spring.main.web-application-type=none"
```

任务/机制语料与地图同步的回滚见 `docs/md/知识库口语问答重构方案.md` 第四节。
**回滚已实测**：清除 83 条 / 49 条后，块总数都**精确回到 2,649**。

### 2.4 什么时候必须重启

派生/导入完成后**词条表会自动补**（见提交 `c97f41e`），所以新块**立刻**对关键词路可见，
不必重启。若跳过这一步，就要等下次启动 `KbTermStore.init()` 时补齐。

## 3. 回归基线：怎么跑、门槛是什么

```bash
# 黄金集（42 题，需要网络：会调向量与重排模型）
mvn test -Dqqbot.golden.rerank=on -Dtest=RetrievalGoldenTest

# 地图/地点端到端（需要网络）
mvn test -Dqqbot.map.sync=on -Dtest=LocationCorpusE2ETest

# 任务/机制端到端（需要网络）
mvn test -Dqqbot.wiki.import=on -Dtest=WikiArticleImporterE2ETest
```

**两层门槛**（黄金集自带断言，不达标就红）：

| 条件 | entity R@1 | entity R@5 | colloquial R@1 | 闲聊干净率 |
|---|---|---|---|---|
| 重排可用 | ≥83% | ≥95% | ≥75% | ≥80% |
| 只有向量 | ≥58% | ≥83% | R@5=100% | — |
| 没有向量 | 不做断言（避免无网误红） | | | |

> **为什么分两档**：重排与向量都要联网。没有网络时不该把构建卡红，
> 但也不能因此把门槛去掉 —— 所以按"能力可用性"分档。

总数要降下来得靠 Repository 化，那还没做。

## 6. 已知缺口（**没有做完的，不要当成做完了**）

1. **任务/机制的中文检索只有 2/4**（端到端测试实测）。
   根因：导入块是英文标题+英文正文，而语料里有 2,649 条中文物品块。
   已修一半（`NameZhIndex` 从语料挖中英对照）。剩下的两种原因不同：
   - 「独眼巨人」类：Boss 页已改名，但**正文太短** → 需给文章块补**中文摘要**
   - 「怎么制作护甲」类：`Crafting` 这类机制词条**语料里根本没有译名**，
     `NameZhIndex` 刻意返回 null（不编） → 需**机制别名表**人工补一小批（Gameplay 只有 11 篇）
2. **`gap` 类仍有约 25 块垃圾**（黄金集里"干净率 0%"）。
   已验证一种做法**行不通**：要求"字面证据"会误杀 colloquial 的「氨液腺」
   （提问"氨液腺"命中"氨腺"，靠向量语义救回，没有字面重合）。
   即：**用 gap 的修复换 colloquial 的破坏，不划算**。需要另想。
3. **`config` 包仍被 16 个包依赖**（S2 只做完了 `GuardProperties`）。
   `KbProperties`(13 依赖方) / `QaProperties`(10) / `MediaProperties`·`CommandProperties`·`LogProperties`(各 7) 可同法办理。
4. **Repository 化没做**（S1 第二步）。做完才能打开 ArchUnit R5（`java.sql` 只许出现在 `persistence`）。
5. **反向 `qa → kb` 仍在**（3 处：`QaCollector` 用 `kb.Glossary`/`KbRetriever`/`KbTrace`）。
   要解它得把 `KbTrace` 挪成中性 DTO。
6. **Phase 0.3 探针去硬编码**未做（18 处 / 13 文件；4 处探针引用的
   `server/data/kb/chunks.jsonl` 已归档，是死代码；3 个截图脚本依赖 Linux-only 路径）。
7. **`web/src/shared/api/types.ts`（679 行）是手抄后端 DTO**，`TermPanel.vue` 1,720 行 —— 都还没动。
