二、防护是什么，为什么不算加密

站点在 /enc.js 里放了一套自制流密码，所有 JSON 数据都不以文件形式直出，而是走一个统一接口按需下发密文。机制如下。

密钥推导

脚本内嵌四个 32 字节数组，逐字节异或即得主密钥。密钥就在文件里，没有任何外部输入。

// enc.js 开头的原样逻辑
for (var o = 0; o < 32; o++) r[o] = t[o] ^ s[o] ^ n[o] ^ i[o];
// r 即主密钥，t / s / n / i 就是文件里那四串数字
a["wki"] = { k: r, e: "/wiki-data/api/serve_wikidata" };

取数与解密

POST /data/api/serve_hubdata.php
Content-Type: application/json

{"k":"668d0ba0a711c44b","t":"t3d_vox_index"}

响应体是 前 16 字节 nonce + 密文。解密是标准 CTR 结构，用 SHA-256 当伪随机函数：

// 逐 32 字节生成密钥流并异或
const block = new Uint8Array(52);
block.set(key, 0);              // 32B 主密钥
block.set(nonce, 32);           // 16B 随机前缀
// 末尾 4B 小端计数器 counter
const ks = await crypto.subtle.digest("SHA-256", block);
plain[i] = cipher[i] ^ ks[j];

这不是加密，是路径混淆。算法、密钥、端点、数据清单全部随页面明文下发，浏览器能解开，任何脚本都能解开。它挡住的只是直接 curl 拿文件的顺手行为。

附带发现：站点还劫持了 window.fetch，凡是命中数据表路径的 GET 请求都被本地解密后返回一个合成 Response。因此前端代码里写的是 fetch("/data/3d/vox/index.json")，看起来像在读静态文件。

关键点：体量最大的四个文件全部明文直出。被混淆包住的只是体积最小的那几个 JSON 元数据。

terrain.bin 的结构

头部 32 字节，取第一个 u32 小端读为 0x31544D45，即魔数 "EMT1"；随后是版本 1、网格边长 2560、平面数 3。正文是三个连续平面：

平面类型长度
高程u16 小端2560² × 2 = 13,107,200 B
材质索引u82560² = 6,553,600 B
生物群系索引u82560² = 6,553,600 B

合计 32 + 4 × 2560² = 26,214,432 B，与实际文件大小逐字节吻合。

六、风险与边界

该站 robots.txt 明确禁止抓取这些路径：/map-data/、/data/、/api/、/map-app/ 全部在 Disallow 列表内。上面所有路径都在其禁止范围内。

  • 数据所有权：点位坐标、材质颜色、地形高程本质是 Keen Games 的资产。gamevault.in 是第三方粉丝站，它对这些数据没有处分权，我们更没有。
  • 来源标识泄露：terrain-palette.json 里直接写着游戏内部构建串 1234127|^/game38/trunk|2026-10-02T20:02:56，terrain-atmosphere.json 里是 keen::AtmosphereResource 7cb4a335-… 与 keen::Biome 枚举名。这坐实了数据是从游戏本体读出来的。
  • 对站点的影响：对方是单人维护的粉丝站，服务器是共享主机。批量拉取会直接伤到它。

建议的处理方式：

  1. 合法路径优先。本项目现有底图来自 enshrouded.wiki.gg，许可为 CC BY-NC-SA 3.0 且已在页脚署名，这条路是干净的，应继续作为主线。
  2. 本次只做小样本验证与机制学习，不做批量镜像，不把第三方数据入库再分发。
  3. 中文译名可以用来交叉校验我们自己的人工标注，但应自建而非整表照搬。
  4. 坐标到米的换算结论来自站点数据推导，仍建议按原计划做一次游戏内实测确认，再写进配置。
