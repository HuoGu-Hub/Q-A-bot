「显示群」「显示 QQ」勾了没反应，以及 user / nickname / QQ 号三个疑问

诊断与修复报告 · 2026-10-24 · 命令系统 · 板块与指令

三个问题其实是同一条链断在两个地方：后台把 showGroup / showUser 正常存进了库，但服务端渲染从来没读过这两个字段；变量面板又把「列表变量」和「全局变量」混在一起展示，于是 {user} 看着和 {nickname} 重复，QQ 号变量则被配置开关挡住，面板里根本不出现。

一、现象、根因、状态

现象根因状态
勾了「显示群」「显示 QQ」，群里看到的内容没有变化 DataPolicy.marksGroup() / marksUser() 只有测试在调用；板块列表由 BoardListFormatter 排版，它拿不到「查询发生在哪个群」，也没有拼来源的代码。指令侧更彻底：指令不读任何跨群数据，这两个开关对它从来就是空转。 板块已修
指令已隐藏
{user} 与 {nickname} 像是重复参数 两者来源不同：{user} 是发这条命令的人的昵称，{nickname} 是记录发起人的昵称。但板块列表只认 nickname，{user} 插进每条格式里会原样输出成文本，看起来既重复又没用。 已按编辑区拆分
没有 QQ 号参数可选 指令里它叫 {user.id}，默认被 app.commands.allow-user-ids=false 关掉；板块的变量表里原本根本没有 QQ 号。另外板块手写的 list / help 回复此前完全没有经过变量渲染，插什么都是死文本。 已补

二、本次改了什么

1. 板块列表真的会标出来源了

BoardListFormatter 新增 render(board, records, viewerGroupId)：只给别群的记录追加来源，本群记录不标，避免每行都挂一句「来自本群」。

#2 满员了 · 来自 300 · QQ 201

两个开关分别控制「来自 群号」与「QQ 号」。BoardRunner.query() 现在把查询所在的群号传进去，私聊传 0 时按「全部都是别群」处理。

2. 板块的 list / help 回复接入变量渲染

编辑页在这两个输入框上也摆了变量按钮，但之前 BoardRunner 直接把原文发出去。现在只有手写内容走 VariableRenderer，自动生成的命令目录保持纯文本，不会被当成模板二次解析。

3. 变量面板按当前编辑区切换

列表头 / 每条格式 / 空列表：只显示列表变量，新增 {user.id}「发起人 QQ 号」，勾了「显示 QQ」才出现。list 回复 / help 回复：只显示全局变量，{user} 在这里就是发命令的人。

列表变量现在是：{id} {when} {nickname} {text} {group} {count} {path} {params.参数名}，外加按开关出现的 {user.id}。预览框也同步显示来源后缀，勾选后立刻能看出效果。

4. 指令编辑器去掉空转的范围设置

指令不读跨群记录，所以「范围 / 群号 / 显示群 / 显示 QQ」对指令没有任何效果，已从指令编辑器移除，只保留「私聊」；板块编辑器保留这些设置并真正生效。

三、现在怎么用

板块要跨群展示来源

  • 范围选「所有群」或「指定群」并填群号；
  • 勾「显示群」，别群记录的行尾出现 · 来自 群号；
  • 勾「显示 QQ」，行尾再加 · QQ 号，同时变量面板开放 {user.id}，可以自己安排它在行里的位置。

指令回复里要打 QQ 号

到「设置 → 指令系统 → 允许 {user.id}」打开。变量页右上角会从「{user.id}/{group.id} 未启用」变成可用；关闭时模板里的 {user.id} 会渲染成「（未启用）」，不会静默消失。

四、验证

  • 新增 3 个单测：只标本群外记录、只勾显示群不带 QQ、{user.id} 受开关控制；mvn test（BoardListFormatter / BoardRunner / BoardStore / AccessController / BoardAdminService）通过。
  • vue-tsc --noEmit 与 vite build 通过，构建产物已同步到 server/web-dist。
  • 前端 dev server 会热更新；后端 8080 需要重启一次，Java 改动才会生效。

五、边界与遗留

指令的数据范围字段仍在库里

老数据可能存过 ALL 之类，但指令没有「读取别的群的记录」这条路径，所以它依旧不产生效果。等以后接了动作类执行器（查记录、撤销记录）再按设计文档启用；在那之前不把它摆出来，比摆出来不生效好。

本群记录不标来源是刻意选择：列表大部分时候都在本群内，逐行标「来自本群」只会把真正需要的信息淹没。
