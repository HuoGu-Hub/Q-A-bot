后端：接口对账

做法是把两边的路径都抽出来做减法，不靠人眼扫。

  • 后端：docs/openapi.json 里 229 个操作，另从 236 处 mapping 注解抽一份带 类名#方法名:行号 的路由表，两边先对齐，避免拿过期契约判死。
  • 前端：web/src 里 221 个调用点，模板串里的 ${...} 归一成 {}，补上 /admin/api 与 /api/public/v1 前缀。
  • 外部入口单独算：/onebot/event 由 NapCat 回调，本来就不该出现在前端。

第一遍跑出 32 条「前端调了但后端没有」，逐条看完全是对账脚本的问题：一类是把查询串 ${q} 当成了路径段，一类是把注释里的 adminApi.post 当成了调用。修正后是 0 条。

反方向剩 37 条孤儿。逐条确认调用方之后，16 条删除，21 条其实有人用 —— 图片、SSE、下载这类地址不是通过 adminApi 发的，靠字符串匹配看不见。

留着没删的

这 5 条也没人调，但删掉等于砍掉一项能力，先留着等你定。

接口为什么留要动的话
POST /admin/api/password管理员自助改密，后台没有入口补一个「账号」页，或删掉这条能力
POST /admin/api/logout-all撤销所有会话与信任设备，属于安全兜底同上
GET /admin/api/guard/metricsGuard 预算与拦截计数，运维排查用接进统计页
GET /admin/api/commands/{id}/policy有单条策略的测试覆盖，批量接口才是页面在用删的话连测试一起删
GET /api/public/v1/map/search公开接口，项目内没人调；外部脚本看不到确认无人调用后删
