时间参数能写什么

命令系统 · 参数类型「时间点」 · 解析器 MomentParser · 2026-10-24

时间参数只有一套口径：东八区墙上时间。时刻必须带冒号写成 21:30；只写日期不写时刻会直接报错，不会默认成零点。下面例子都假定「现在」是 2026-10-24 09:32，星期六。

二、两条容易踩的规则

「今天 / 今晚」不会顺延。 只写时刻时的「顺延到明天」是在回答「下一次到这个点是何时」；而「今晚9:30」在 22:00 说出口，指的就是已经过去的时间。解析器会如实返回今天 21:30。一次性任务落库时会被拒绝，回「那个时间已经过去了，换个时间」；每天 / 每周这类周期任务只取钟点，按规则从下一次到点算起。
不带年份的日期会跨年。 10 月 24 日写 10-18 21:30，得到的是 2027-10-18。想留在今年就写全年份 2026-10-18 21:30。

三、不认的写法

输入结果说明
21点30、21时30报错时刻只认冒号；报错会提示「只认冒号，不认「点」」
9点半、晚上9点、明天晚上9点半报错不认「点 / 半 / 早上 / 下午 / 晚上」这类口语
明天、2026-12-01报错只有日期没有时刻
24:00、21:60报错小时 0–23，分钟 0–59
2-30 21:30报错不存在的日期
9:30:00报错不支持秒
现在、一会儿报错相对时间只认「N 分钟 / 小时 / 天」

四、多值与落库

「时间」参数是可多值的：用顿号、全角逗号或半角逗号分隔，每段单独解析。

#时间-07:00、14:00、21:30#
  • 一次：完整时刻（日期 + 钟点）原样落库，过期就没得发。
  • 每天 / 每周几 / 每 N 天：只保留钟点，日期部分不参与计算；每3天 的起算点是记录创建时间。
  • 落库形态：一次性存 ISO 时刻；周期存 HH:mm，多个值按顺序排。
  • 回执与列表里显示的是解析后的人话，例如「每天 21:30」。

五、如果你问的是 {time} 变量

那个不是解析输入，而是输出当前时刻，格式固定：

变量输出示例格式
{time}14:32HH:mm
{date}2026-10-24yyyy-MM-dd
{datetime}2026-10-24 14:32:07yyyy-MM-dd HH:mm:ss
{weekday}星期六星期X
{uptime}3 小时 12 分运行时长，非时刻

六、改动与验证

本次修了一处语义错误：今天 / 今晚 原来被当成「只写时刻」，时刻一过就悄悄变成明天。现在它们锚定当天，由板块在落库时拒绝过期时刻。新增 MomentParserTest，把上面这些写法全部钉住；mvn test 通过。

想支持「21点30」「9点半」「晚上9点」这类口语，需要再加一层时刻语法与 12/24 小时换算；目前故意不猜。
