指令系统 · 触发与参数重构

斜杠路径与井号参数

命令一律以 / 开头，后面可以跟多级路径；每个取值用 #变量名-值# 单独标注。@ 只是入群闸门，不参与语法。

一句话结论

一条命令拆成三段：命令路径、井号参数、自由文本。路径按最长匹配一级一级吃词，/set /output 是两级命令，/xxx /help 是取这条命令的说明。参数不再靠位置猜，而是自带名字，顺序随意、中英皆可、值里可以有减号和空格。命令在库里声明自己的参数表，解析失败就回一句指名道姓的用法提示。

上一版错在哪

上一版把 @机器人 记录-打本-20:00 当成新触发形态，这是错的。@ 在 QQ 里是「叫人」的语义，把它塞进命令语法会让群友分不清「@ 是叫人还是下命令」。另外破折号当分隔符要跟日期、内容里的连字符持续打架，得靠回溯猜。这一版把这两件事都收回去。

要素上一版这一版
触发@机器人 命令-值/路径 不变
@ 的角色语法的一部分只是群里必须 @ 的准入闸门
取值分隔破折号，需回溯猜#名字-值#，自带边界
参数顺序有位置含义无所谓，按名字取
层级无/set /output 多级路径

命令长什么样

/路径 /子路径 … #变量名-值# … 自由文本

三段都是可选的，但至少要有一个路径。参数与文本可以任意穿插，解析器只摘走形状正确的井号段，剩下的全是文本。

输入路径参数文本含义

/xxx /helpxxx——只看 xxx 的说明

触发的前置条件

命令能被执行，先要过准入。这几件判定不新增开关，全部沿用已有的那一份：

条件读的是哪个设置说明
群里必须 @ 机器人app.guard.access.require-mention-in-group与普通问答共用同一个开关。指令不再有自己的一份，同一个语义不留两个开关。
私聊能不能用app.guard.access.private-chat-policy私聊默认关闭，与问答同一份策略。
黑名单群黑名单 · 用户黑名单由 Access.denial 一处判定，指令与问答不会得出两个结论。

现在库里有一个重复的 app.commands.require-mention，以及后台「指令系统」分组里对应的「命令必须 @」条目。这一版把它删掉：同一个语义留两份开关，就会出现「@ 了机器人，问答回了、指令没回」或者反过来这种自相矛盾的状态，而且不报错。

app.commands.require-slash 一并删掉。命令一律以 / 开头 —— 路径与井号参数的语法都建立在它之上，关掉前缀之后这套语法就没有定义了。

指令在 Guard 之前跑，所以 @ 判定必须在命令匹配之前自己判一次。判法与 MentionRequiredStage 一样，抽出 Access.mentionSatisfied 一个方法给两边共用。

路径怎么解析

规则是最长匹配：能吃进路径的词就吃，吃不动就停，停下的地方开始是参数和文本。

  ① 取第一个词，与一级路径精确比较         大小写不敏感
     不在表里 → 不是命令，交回普通问答

  ② 看下一个词以 / 开头？
     且「当前路径/这个词」在表里 → 并入路径，回到 ②
     否则 → 停在当前路径

  ③ 停下的位置之后，先摘 #名字-值#
     剩下的就是自由文本

  特例：/路径 /help
     若「路径/help」没注册 → 认作帮助修饰符，只回说明不执行

这条规则同时解决了两件事：多级命令不必额外声明层级语法，而文本里出现的 /api/getUser 只要不是注册过的子路径就不会被误吃。

  /联网 /api/getUser 是什么
    路径 = 联网            api 不是联网的子路径，停在第一级
    文本 = /api/getUser 是什么
help 是保留字。任何路径都不能把子命令命名成 help，否则第 ③ 步的判定会有歧义。新增指令时后台会直接拒绝这个名字。

参数怎么写

形状固定为 #名字-值#，名字与值在第一个减号处切开，所以值里可以照常出现减号、空格、斜杠和冒号。

  #time-21:30#          名字 time    值 21:30
  #date-2026-10-18#     名字 date    值 2026-10-18      值里的减号不动
  #时间-晚上八点#        名字 时间    值 晚上八点         中文名一样用
  #text-晚上打本-集合#   名字 text    值 晚上打本-集合
规则说明
名字字符集汉字、字母、数字、下划线；不能含减号、井号、空白
大小写名字与路径都不敏感，值原样保留
顺序随意，可出现在文本前、中、后
重复同一个名字出现两次 → 报错，不静默取后者
全角＃ 与 # 等价，中文输入法不会卡住
空白路径与参数之间的空白忽略；名字与值去首尾空白，值内部空白原样保留
值里的变量值可以写 {系统变量}，先展开再做类型校验，只展开一次
形状不符没有减号的 #1# 不算参数，原样留在文本里
没有参数表整段都是文本，一个井号段都不摘 —— 老指令的文本里出现 #xxx# 不该被判成参数错误
字面井号文本里真要写 # 时用 \# 转义

空白怎么处理

QQ 里空格很容易多打，参数段又会整段摘走，不做归一就会输出「文本前多一个空格」这种脏结果。规则按位置分：

位置处理
路径与参数之间连续空白当分隔符，空片段丢弃。/set　/output 与 /set /output 等价
参数段的周围连同两侧空白一起摘走，原位不留空格
自由文本按参数段切开，每段去首尾空白、丢掉空段，再用一个空格接回去
参数名与值首尾空白去掉，内部空白原样保留
文本内部的换行保留，方便写多行输出

全角空格、制表符与半角空格等价，不间断空格也一并归一。真正要保住的是值内部与文本内部的空格：#text-晚上 打本# 的值是「晚上 打本」，这两个词之间的空格是内容，不该被吃掉。

  /set   /output    #time-21:30#      文本
    路径 set/output      参数 time=21:30      文本 = 文本        前后多余空格不进入文本

  #text-  晚上   打本  #   →   值 = 晚上   打本                   值内部空格保留

路径也可以连着写：/set/output #time-21:30# 文本 与 /set /output … 等价，两种写法都认。

参数由命令声明

后台新增指令时填一份参数表，它就是这条命令的契约：解析、校验、帮助、模板取值全靠它。

字段含义例
name井号里的变量名，中英皆可time 或 时间
type取值类型moment
required缺了是否算失败true
default可选参数的默认值21:00
description帮助里那一行说明每天几点发
example帮助与回执里的样例21:30
options枚举类型的候选值，其余类型为空daily / once
类型接受什么归一成什么
text任意文本原样字符串
int十进制整数long
moment21:30、明天21:30、10-18 21:30东八区的时刻
enum参数表里列出的候选值规范值

时间只认 AppTime 那一套东八区口径，解析、落库、展示、扫描全链路一致，不引入第二套换算。模板里用 {arg.time} 取值，老命令的 {args} 与 {args.N} 原样保留。

失败要说清是哪一项

回执固定三段：哪个参数、期望什么、完整用法。不猜、不静默丢弃。

  没有 #time# 这个参数。这条命令可用：#date# #text#
  用法：/set /output #time-21:30# <文本>
  例：  /set /output #time-21:30# 晚上打本集合

  #time# 的 25:99 不是有效时间，示例：21:30
  缺少必填参数 #text#

文本里的变量

命令里要发出去的文字，可以直接写 {变量名}，取值表与管理端口令里那一套完全相同，不另学一套语法。渲染仍然只有 VariableRenderer 一份实现。

语言只由创建者决定，系统不做转换，也不做别名表。命令名与参数名在新增指令时自己起，中英皆可；系统变量名固定是英文这一套，写 {用户} 会被当成未知变量原样保留，不会被猜成 {user}。同一个值不留两个名字。

参数一律用 {arg.名称} 取，所以即使有人把参数起名叫 user，也不会和系统变量 {user} 撞车：{user} 永远指系统变量。

变量值例
{user}触发者昵称，群里优先取群名片示例用户
{group}本群名称与群号本群(100000004)
{bot}机器人昵称示例助手
{time} {date} {datetime} {weekday}当前时刻21:30 · 2026-10-18
{uptime}已运行时长3 小时 12 分
{kb.count} {kb.terms}知识库规模4,131
{qa.total} {qa.today} {qa.hitrate}问答统计87.3%
{cmd.total} {cmd.list}指令表本身可用指令：…
{arg.名称}这条命令当次收到的参数值{arg.time} → 21:30
{text}摘掉参数段之后的自由文本晚上打本集合
{user.id} {group.id}高级变量，默认关闭100000005

生效范围分两种时机：模板回复与命令尾部的自由文本是用时展开，参数值是解析时展开一次。数字与时间参数展开完就是数据，不再当模板。

什么时候取值

场景取值时刻说明
即时命令说话那一刻{time} 就是你发消息的时刻。
定时任务发送那一刻内容按模板存盘，到点才展开。所以 {time} 是真正发出去的时刻，不是设置它的时刻。
  即时
  /say {user} 你好，现在是 {time}
    → 张三 你好，现在是 21:30

  定时
  /set /output #time-21:30# 今晚 {time} 打本，{date} 见
    创建时只存模板
    21:30 发出：今晚 21:30 打本，2026-10-18 见

参数值里的变量

值本身也可以引用系统变量，写成 #名字-{系统变量}#。展开发生在解析阶段，也就是摘出井号段之后、类型校验之前。

  #name-{user}#          → 先展开成 张三，再当一个 text 值
  #time-{time}#          → 先展开成 21:30，再按 moment 解析    顺序不能反
  #group-{group.id}#     → 100000004

顺序为什么必须在类型校验之前：{time} 本身永远不是合法时间。先校验就永远过不了，先展开才拿得到 21:30。反过来，int 与 moment 参数因此也能吃变量，不必只留给文本。

位置取值时刻原因
#名字-值# 里的变量解析那一刻参数是这次命令的输入，值当场定下来；类型校验必须在展开之后。
自由文本里的变量用时那一刻，定时任务到点才展开文本是要发出去的话，{time} 应当是发送时刻。

两条边界：

  • 展开只做一次。展开得到的字符串不再被扫描，所以 #text-{cmd.list}# 拿到的是那一刻的指令列表，不会在里面继续展开。
  • 值里不解析 {arg.*}。参数之间不该互相引用，否则解析顺序会变成隐式依赖。

{arg.名称} 另走一条路：自由文本里写 {arg.time}，用时从任务行存着的参数 JSON 取值代入。

变量现在会作用在群友输入上，三条安全约束一条都不能松。
  • 不提供 {config.*} {env.*} {server.*} 这类能读系统信息的变量。
  • 替换进去的值不再二次解析。有人把群昵称改成 {cmd.list}，发出去的就是那几个字，不会真的展开一次。这条原来只是防模板注入，现在升级成硬约束。
  • 未知变量原样保留，方便一眼看出拼错，而不是静默变成空。

最坏情况也就是让机器人把本来就公开的统计数字打出来。若要让某条命令不吃变量，把它的自由文本按字面量处理即可，参数表加一个开关就够。

单命令帮助

/路径 /help 只回这一条命令的说明。内容由参数表自动生成，后台可以整体覆盖成手写文案。

  /set /output — 设置一条定时输出的文本
  用法：/set /output #time-21:30# <文本>
  参数：
    #time#  时间点  必填  例 21:30
    #date#  日期    可选  例 2026-10-18
    #text#  内容    必填  例 晚上打本集合
  示例：/set /output #time-21:30# 晚上打本集合

不带参数的裸命令 /set /output 也回同一份说明，这是「发了命令但不知道要传什么」时最自然的兜底。

命令类型与动作

类型仍是三类，判断依据是「要不要花钱、要不要落库」。

kind做什么走 Guard 与预算例
template渲染模板秒回不走/help
agent把文本当问题交给模型走/qa #mode-none# 今天什么版本
action交给注册的执行器，写库或查库不走/set /output …

动作用注册表分发，不写 switch。每个动作是一个类，声明自己的参数表与用法，执行时拿到校验过的 CommandArgs 和上下文，返回一句回执。动作被删掉之后，绑定它的命令在解析阶段就当作停用并记一条告警日志，不会在线上抛 ClassNotFound。

定时输出：一条完整的链路

就用你给的那个例子，三个动作组成闭环。它们都是内置命令，不可删除，回执文案可在后台改。

命令动作参数回执
/set /outputschedule.create#time# 必填 · #date# 可选 · #text# 必填已记下 #3：今天 21:30 在本群输出「晚上打本集合」
/list /outputschedule.list无本群待发 #3 今天 21:30 晚上打本集合
/del /outputschedule.delete#id# 必填已撤销 #3

带 #date# 的只在指定那天发一次，不带就是每天同一时刻发。删除按编号，因为按内容匹配会误删——两句「打本集合」分不出是哪条。

内容与参数都按原文存盘，到点才展开变量。所以 {time} 拿到的是发送时刻，改文案也不必重建任务。

任务表

  bot_schedule
    id           INTEGER PK        // 回执里的编号
    group_id     INTEGER           // 0 = 私聊
    user_id      INTEGER           // 创建者，删除权限的依据
    content      TEXT              // 到点要发的那句话，变量保持模板形态
    params       TEXT              // 当次参数的 JSON，供 {arg.x} 在发送时取值
    fire_at      TEXT              // 下一次触发时刻，UTC 存盘
    repeat_rule  TEXT              // once / daily，带 #date# 的是 once
    status       TEXT              // pending / sending / sent / failed / expired / canceled
    attempts     INTEGER
    last_error   TEXT
    created_at   TEXT
    sent_at      TEXT

索引建在 (status, fire_at)，扫描只走这一条。周期任务发完之后按 repeat_rule 推下一个 fire_at 并回到 pending。

扫描器要定的五件事

问题决定理由
多久扫一次10 秒，首次延迟 15 秒群聊提醒差十秒能接受，扫太勤只是空转。
会不会重复发先 UPDATE … WHERE status='pending'，更新到 1 行才发同一行只能被一个 tick 抢到，多实例共用同一个库也安全。
停机错过了怎么办30 分钟内补发，超过标记 expired半夜重启后补发一条「下午三点集合」只会让人困惑。
发送失败怎么办重试 3 次并退避，仍失败标 failed协议端短暂掉线不该丢任务，也不能无限重试。
线程池spring.task.scheduling.pool.size 调到 2Spring 默认调度池只有一个线程，别的定时任务会被这个 10 秒 tick 挤住。

扫描器不碰协议客户端，只调出站发送器：群聊走 sendToGroup，私聊需要新增 sendToPrivate。两条路共用出站过滤、分片与节流。定时发送不能成为绕过内容过滤的侧门。

其他群友拒绝，回「#3 不是你建的」
别的群查不到，任务是群内资产

权限判定走 min_role，顺手补上「字段只存不判」那个缺口。角色由路由层归一化成 owner / admin / member / none 放进上下文，动作层不解析 OneBot 的 JSON。

组件与依赖

新代码落在 command 包，持久化落 persistence。三条既有护栏直接约束实现方式：

  • 业务包不得依赖 config —— 扫描器与动作的配置走只读接口，由 config 侧实现。
  • 只有 outbound 与 router 能碰 OneBotApiClient —— 扫描器只持有 OutboundSender。
  • 持久化之外不得出现 java.sql —— 新表所有 SQL 进 ScheduleRepository。

验收清单

  • /xxx /help 只回 xxx 的说明，不回全局列表。
  • /联网 /api/getUser 是什么 的文本完整保留，路径停在「联网」。
  • #date-2026-10-18# 的值是 2026-10-18，没被切成两段。
  • 参数顺序颠倒、放在文本之后，结果一致。
  • #time-25:99#、缺 #text#、重复 #time# 三种失败都指名到参数。
  • 文本里的 #1# 不被当成参数。
  • /set /output #time-21:30# 文本 切出的文本是「文本」，没有前后空格。
  • #text-晚上 打本# 的值保留中间那一个空格。
  • /say {user} 你好 发出的文字里是触发者昵称。
  • 定时任务里的 {time} 是发送时刻，不是创建时刻。
  • 触发者昵称含 {cmd.list} 时原样发出，不被二次展开。
  • 拼错的 {usre} 原样保留，不静默变成空串。
  • {用户} 不被当成 {user}，原样保留。
  • 变量页能搜到 kb.count，「取当前值」后显示真实条数。
  • 变量页明确标出 {arg.x} 不能写在参数值里。
  • #name-{user}# 拿到触发者昵称；#time-{time}# 先展开成 21:30 再通过 moment 校验。
  • #text-{cmd.list}# 展开出的指令列表里若含 {...}，不会被再展开一次。
  • 跨群删除查不到，非创建者被拒，群管可以删。
  • 停机 10 分钟后重启补发，2 小时后重启标记过期不补。
  • 定时内容命中敏感词时被出站过滤拦下，与即时回复同一套判定。

风险

风险处置
变量作用到群友输入上取值表只含公开信息，替换值不二次解析，未知变量原样保留。最坏情况是把公开统计打出来。
文本里恰好出现 #名字-值# 形状用 \# 转义；解析失败时把原文回显，让群友一眼看出被摘走了什么。
子路径名与文本冲突只有注册过的子路径才会被吃进路径，其余原样当文本。
定时发送变成骚扰工具每人待发上限 5 条、内容 200 字、沿用独立限流，到点仍走出站过滤。后续可加免打扰时段。
周期任务堆积周期以行为单位更新同一个 fire_at，不预先展开成多行；到点失败三次自动停并私聊创建者。
SQLite 写锁写入是单行插入，量级是每人每天几条；扫描每 10 秒读一次，冲突可以忽略。

已经定下的事

1. #date# 决定周期。带日期只发一次，不带就每天同一时刻发。回执里写明是「只此一次」还是「每天」，不让群友自己猜。

2. # 用 \# 转义。解析失败时把原文一并回显，让人一眼看出哪一段被当成参数摘走了。

3. 参数值里的变量在解析时展开。展开在类型校验之前，所以数字型与时间型参数也能吃变量；展开只做一次，结果不再当模板。

4. 自由文本里的变量在用时展开。内容按模板存盘，所以 {time} {date} 是真正发出去那一刻的值；{arg.名称} 用当次参数的 JSON 一起展开。

5. 空白按位置归一。参数与路径之间的空白忽略，名字与值去首尾空白，值内部与文本内部的空格保留。

6. 不做变量别名表。语言由创建者决定，命令名与参数名自己起；系统变量固定英文名，同一个值不留两个名字。

7. 变量只读可查。不做增删改，只提供查看：能写什么、什么时候取值。清单与命令编辑器共用一处来源。

8. @ 判定只有一处。命令匹配不再带自己的 require-mention，读准入设置；黑名单与私聊策略同样读准入那一份。
