雾锁王国 3D 地图实现方案

3D 地图与标点显示的三种路径 · 含实测结论与工作量评估

项目：飘雪喵问答机器人　｜　评估日期：2026-10-15　｜　现状：公开站 /map 为 2D 画布

一、结论

  1. 能做，而且 3D 场景本身不难。难点不在渲染，在高程数据从哪来。
  2. 你现在手上的底图不含地貌信息，无法反推出地形起伏。已实测，见第二节。
  3. 所以「游戏地图」和「找地方」这两件事应该分开：2D 保留为主界面，3D 做可选视图。3D 在找点上并不比 2D 好，它的价值是展示与氛围。
  4. 建议先做不依赖任何新数据的方案 A，把 3D 框架立起来；真地形作为后续升级，优先走方案 B 的授权路线。

二、实测：底图能不能反推地形

项目已缓存 Embervale 底图 64 张 1280×1280 瓦片，覆盖 10240×10240，与画布 extent 完全一致。这看起来是个现成的高程来源：地图上的明暗就是山体阴影。于是做了实测。

把底图亮度当作高程代理，与本项目已有的真实高程图做配准搜索，遍历四种翻转与 ±40 像素的平移：

对照方式相关系数
原始对齐+0.109
最优配准，翻转 rot180 加偏移 36,36+0.160

此路不通。最优配准下相关系数仅 +0.16，说明底图的明暗与真实地形高度基本无关。底图内容偏平，且被 Shroud 紫雾与水体配色主导。想靠它做出可信的地形起伏，只会得到一片随机噪点。

三、三条路线

路线高程来源授权视觉效果工作量
A 立体展示层无，用平面加厚度现有 CC BY-NC-SA 底图有透视、可旋转、点位立体2 至 3 天
B 授权接真地形gamevault 的高程数据需向对方取得许可与目标站点一致1 至 2 天，叠加在 A 之上
C 自建提取管线自己安装的游戏本体完全自主与目标站点一致2 至 4 周

方案 A · 立体展示层 建议先做

不引入任何新数据，把现有底图与点位放进 Three.js 场景，做出真正的三维观看体验。

  • 地表：把 64 张瓦片拼成贴图，按块切成纹理按需加载，避免一次拉 131MB。地表做成带厚度的地块，侧边给一个深色截面，视觉上像一块浮空的立体模型。
  • 点位：1703 个点位用实例化 billboard 绘制，直接复用现有分组图标。每个点位加一道竖直光柱，让它在斜视角下也能被看见，并按距离做遮挡与淡出。
  • 相机：OrbitControls 做旋转、俯仰、缩放；限制俯仰角不小于 25 度，避免看到地表的零厚度侧面。
  • 命中检测：射线拾取替代现有的屏幕距离命中。现有 hitTestAll 的「同一点位堆叠」语义要一并迁移，尖塔那种重叠点位在 3D 里更容易被挡住。
  • 坐标对接：mapMath.ts 已经把换算拆成了纯函数，3D 只需再加一层 world → 三维坐标 的映射，crs 与 world 两层直接复用，不需要改动现有 2D 代码。
  • 性能：three 打包后约 600KB，必须走动态 import，只在用户切到 3D 时才加载，否则会拖慢主要用于找点的地图页。

要接受的前提：没有真实起伏。这块是平的，所有点位都在同一高度。看着比 2D 有层次，但不是目标站点那种「山脉真的立起来」的效果。

方案 B · 授权接真地形

目标站点的高程数据已经把游戏世界烘焙成了 2560² 与 5120² 两级网格，体素边长 4 米与 2 米，另有洞穴体素分块。拿到它，方案 A 的地表换成真实高程网格即可，其余全部复用。

  • 先做的一件事是发信询问。对方站底有 /contact，本身是逆向社区性质的项目。取得书面许可后，无论接数据还是后续维护都站得住。
  • 若对方只肯授权「引用与链接」，退一步是只取高程、自己配色重渲，并在页面署名。
  • 若对方拒绝，直接跳到方案 C，不要绕过 robots 硬接。

方案 C · 自建提取管线

从自己安装的游戏本体读世界数据，自己生成高程。目标站点的前端里就带着这套读取器的实现思路：8×8×8 体素砖块、游程编码的材质与密度双流、以及 zstd 帧的存档容器。

  • 工作量大在存储格式的逆向与校验，以及一次完整的世界烘焙。
  • 好处是完全自主，不依赖任何第三方授权，游戏更新后也能自己重跑。
  • 本项目后端是 Java，需要新写一份体素容器解析；现有物品知识库那条链路与此无关，不会互相影响。

四、建议的落地顺序

步骤内容产出
1先确证 units-per-meter，按勘察结论填 1 并做一次游戏内实测核对米制描述上线，3D 也有了比例依据
2做方案 A，3D 作为 /map 上的可选视图切换可旋转的立体地图与点位
3同时向 gamevault 发信询问授权决定能否进入方案 B
4有授权则接真地形；无授权且确有必要，再评估方案 C真实起伏

五、明确不做的事

  • 不从前端再抓一次地形数据。对方 robots.txt 禁止 /data/ 路径，产品化使用必须先取得许可。
  • 不用程序噪声伪造地形。玩家会拿它和游戏内地图对照，假的起伏只会让人误判位置。
  • 不用 3D 取代 2D。找地方时俯视正交视角是最快的，斜视角反而增加判断成本。

评估方式：拼接项目已缓存的 64 张底图瓦片，与既有高程图做配准搜索验证高程可提取性；阅读 mapMath.ts、types.ts 与公开地图视图确认接入点。
