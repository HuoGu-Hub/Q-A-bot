命令系统 · 重新设计

骨架：一条消息怎么变成一件事

这份文档只讲骨架：消息长什么样、谁有资格发、发出去的东西谁能看到。具体功能都挂在这个骨架上。

一页结论

命令一律以 / 开头，后面是路径、传入变量、文本三样。

每条命令带两把独立的锁：谁能用，和能看到哪些群的数据。公告这类锁死在本群，开黑那类显式放开成跨群。

有一条铁律：写永远只能写发命令的那个群。放宽的只有"读"。

一条消息进来，发生什么

  群友发一条消息
        │
        ▼
  ① 是不是命令？ ──── 不是 ────▶ 当普通聊天，交给问答
     以 / 开头，路径能在命令表里找到
        │ 是
        ▼
  ② 这个人有没有资格用？ ──── 没有 ────▶ 回一句说明，到此为止
     全体 / 管理员 / 群主 / 白名单
        │ 有
        ▼
  ③ 拆参数与文本
     #名字-值# 摘出来，剩下的就是文本
        │
        ▼
  ④ 这条命令能看到哪些群的数据？
     本群 / 指定的几个群 / 全部群
        │
        ▼
  ⑤ 执行：回一句话 / 交给模型 / 做一件事
        │
        ▼
  ⑥ 落库：归属群永远是「发命令的这个群」

②在③前面不是随便排的：没资格的人不该看到参数表的细节，也不该触发任何动作。

命令怎么写

/路径 /子路径 … #名字-值# … 文本

路径按最长匹配一级一级吃词，吃不动就停。所以 /set /printout 是一条两级命令，而 /联网 /api/getUser 是什么 的路径停在「联网」，后面整段是文本。

两种变量，两条路

叫法写法用途什么时候定下来
传入变量#outtime-21:30#群友把值送进系统，给程序做判断收到消息那一刻
传出变量{time}系统把值填进要发出去的文字真要发出去那一刻

为什么必须分开：传入变量要拿去算「什么时候发」，所以消息一进来就得变成确定的值；传出变量的价值就在于「发出来那一刻是几点」，早一秒都算错。

  /set /printout #outtime-每天21:30# 现在是 {time}

  收到消息时  ──▶  outtime = 「每天 21:30」算好并检查合法
                ──▶  文本原样存下：现在是 {time}

  21:30 发出时 ──▶  {time} 才变成 21:30
                ──▶  群友看到：现在是 21:30

两把锁

这两件事以前被混在一起，是错的。能不能用和能看多少数据是两件独立的事：

锁一：谁能用这条命令

档位含义典型用法
全体群里的任何人都能发查公告、找开黑
管理员群主与群管理员发公告、撤公告
群主只有群主改群内规则类
白名单指定的几个人内测功能

另有一个独立开关：私聊能不能用。默认关。私聊里没有群角色，所以「管理员」档的命令在私聊一律拒绝，并且明确回一句「这条命令要在群里用」，而不是含糊地说「权限不足」。

锁二：这条命令能看到哪些群的数据

档位读得到什么写到哪里
本群只有本群的数据本群
指定几个群只在给定的这几个群之间互相可见仍然是本群
全部群所有群的数据仍然是本群

默认是本群。新建一条命令，不加任何设置就是隔离的；要跨群必须有人主动去后台改。

铁律：写永远只能写本群。任何命令都不能替别的群写数据。否则一个人在 1 群发一条，可以伪装成 2 群的内容 —— 跨群可见之后，这种伪造根本查不出来。放宽的只有"读"。

两把锁一组合，就能表达你的两类需求

命令谁能用数据范围结果
/set /printout 发公告管理员本群1 群的公告 2 群永远看不到
/del /printout 撤公告管理员本群只能撤本群的
/lfg /post 发开黑全体本群写入时归属 1 群
/lfg /find 找开黑全体全部群2 群能查到 1 群的那条，并且知道它来自 1 群

注意最后两行：同一条功能的两半，范围可以不同。发布只写本群，查询才放宽。这也是为什么锁要按命令路径配，而不是按功能配。

数据归属与查询

每条落库的记录都带一个归属群，就是发命令的那个群。查询时按「读的那条命令的范围」过滤：

  /lfg /find 今晚有空

  读的那条命令范围 = 全部群
        │
        ├─ 1 群的记录 ✓ 显示，并标注「来自 1 群」
        ├─ 2 群的记录 ✓ 显示，并标注「来自 2 群」
        └─ 3 群的记录 ✓ 显示，并标注「来自 3 群」

  /set /printout 的列表
  读的那条命令范围 = 本群 → 只看得到本群的公告

跨群结果必须标出来自哪个群。不标的话，群友拿着一份联系方式不知道是哪个群的人，跨群就失去了意义。

场景一：定时公告

一次性和循环，都写在一个 #时间-# 里，读起来像人话：

写法意思
#时间-21:30#今天 21:30；已经过了就是明天 21:30，只发一次
#时间-10月20日21:30#10 月 20 日 21:30，只发一次
#时间-每天21:30#每天 21:30，一直发
#时间-每周三21:30#每周三 21:30
#时间-每3天21:30#每 3 天的 21:30

循环的那几种，发完之后从原定时刻往后推一个周期，而不是从「现在」起算。所以一条 21:30 的公告永远是 21:30，不会因为发的时候慢了 5 秒就漂成 21:30:05。

服务停机错过了好几天，恢复后只补最近一个未来的时刻，不连着补发。半夜重启后一口气收到三条「今晚八点开黑」是最烦人的。

群友发：/set /printout #时间-每天21:30# 今晚八点开黑

机器人回：已记下 #12：每天 21:30 在本群发「今晚八点开黑」

如果这条命令的使用权限是「管理员」，而发的人只是普通成员 —— 机器人回：这条命令仅管理员可用。

场景二：撤销

撤销按编号，不按内容。两句「今晚开黑」分不出是哪一条，按内容撤会撤错。

群友发：/del /printout #id-12#

机器人回：已撤销 #12：今晚八点开黑

谁能撤说明
创建者本人自己设的自己能撤
本群管理员与群主撤别人设的
别的群的管理员撤不了。编号在别的群查不到，回「没有 #12 这条」

撤销是打标记，不是删行。谁撤的、原定什么时候发，都还查得到，后台能看到完整历史。

启用开 / 关

私聊可用开 / 关

一张总览表

光有一条条改还不够 —— 权限最怕的是「我以为它没开，其实开了」。所以另加一页只读总览，把每条命令的两把锁并排列出来，一眼能扫出哪些命令开了跨群：

  命令              谁能用    私聊   数据范围      状态
  /set /printout    管理员    关     本群          启用
  /del /printout    管理员    关     本群          启用
  /lfg /post        全体      开     本群          启用
  /lfg /find        全体      开     全部群        启用
  /help             全体      开     ——            启用

「数据范围」那一列里，凡不是「本群」的都标成醒目颜色。这就是这张页面唯一的目的。

需要你定的四件事

1. 使用权限的档位够不够。现在设计四档：全体、管理员、群主、白名单。白名单要在后台另外挂人，是四档里唯一需要额外维护的。如果你觉得「全体 / 管理员」两档就够，可以先砍掉白名单，以后再补。

2. 跨群查询要不要把联系方式摊在群里。按你说的，2 群的群友能查到 1 群那个人的联系方式。我的建议是：列表公开（空闲时间、风格、来自哪个群），联系方式私聊给发起查询的人。理由是群里一刷就是几十个人同时看到，事后收不回来；私聊只给真的要用的人。你要公开刷在群里也行，但得先知道这个代价。

3. 时间怎么写。我推荐把重复规则揉进一个 #时间-#，像「每天21:30」这样读得出来。代价是这个参数的类型不再是纯时间，而是「时刻表达式」。另一种写法是拆成 #重复-每天# + #时间-21:30# 两个参数，更机械但更啰嗦。你选哪种？

4. 编号是不是全系统唯一。我推荐全局唯一：#12 永远只指向一条，日志和工单对得上。查询仍按范围过滤，所以别的群的编号查不到。另一种是每个群从 1 开始编号，好处是群友看不出别的群有多少条，坏处是排查时同一个编号要带上群号才说得清。

和现在代码的关系

不是推倒重来。已经能跑的是：/ 触发、路径最长匹配、#名字-值# 的解析与校验、{变量} 的展开、定时任务的落库与投递、撤销。

这次要补进骨架的是：

  • 两把锁 —— 现在只有"谁能用"的一半，且没有数据范围的概念
  • 数据归属与查询过滤 —— 记录要带群号，读的时候按命令的范围过一道
  • 时间表达式 —— 现在只能定"某天某点"和"每天某点"，缺「每周几」「每 N 天」
  • 权限总览页 —— 现在只有单条命令的设置，没有一眼扫全的地方

做完上面四条，开黑那个功能就是在已有的骨架上加两个命令，不用再动骨架。
