知识库：导入与使用手册

面向操作者。讲清：文档怎么导进来、术语表怎么导、以及哪些东西已经没有了。 设计背景与摄入边界见《知识库摄入边界与激活协议》；格式要求见 知识库文档格式规范.html。

一、现在是什么状态（2026-09-29 之后）

只有一套存储，导入即生效。 旧的 wiki 抓取那一套已经整块删掉：

已经删掉的 说明
wiki 抓取 / 清洗 / 建索引 KbCorpusBuilder、WikiClient、WikiTextCleaner、KbIndexBuilder、GlossaryBuilder
旧语料文件 chunks.jsonl、index.bin、pages.jsonl、raw/、build.json、术语表 TSV
「资料」里的投递 + 邀请码 整块功能下线（资料一律以符合格式的文档导入）
「词条」里按行号改文本块 正文改在「文档」面板，按块 id 操作
那个 app.kb.store 开关 没了 —— 现在就一套存储

数据在哪：SQLite 的 kb_block / kb_block_vec 表（和问答记录同一个库文件）。 旧语料已归档到 server/data/kb/../.legacy-archive/kb-legacy-20260929.tar.gz（13 MB）， 确认不需要了可以直接删。

二、导入文档（主要入口）

管理端 → 知识库 → 文档（这个 tab 是第一个，也是默认落点）。

步骤

  1. 准备文档：按 知识库文档格式规范 产出（标题中文、id 英文、正文翻译成中文）。 产出后先自查：

    ./scripts/validate-kb-doc.sh 你的文档.md

    退出码 0 才算合格。这一步别跳 —— 格式问题在这里最便宜。

  2. 粘贴或选文件（支持 .md / .txt）。

  3. 点「预览会改什么」 —— 只算不改，告诉你：

    新增 N   覆盖 M   无变化 K   库里未被触及 X 块
新增：id1、id2…     覆盖：id3…
⚠️ 提醒：…

    看三个数：

    • 覆盖 M 应该约等于"这次改了几块"。若等于整份文档的块数，说明 id 变了；
    • 新增 N 里出现"标题和库里某块相同但 id 不同"的提醒 → 几乎一定是 id 写错了， 导进去会变成重复两块；
    • 未被触及 X 是库里没被这次导入碰到的块数。

  4. 点「确认导入」 —— 导入即生效（索引自动重载，不用重启）。

导入规则（就一条）

文件里出现的块：id 存在 → 覆盖；不存在 → 新增。 文件里没出现的块：一个都不动。 不区分是否人工改过，一律以最新导入的为准。

所以更新时只给改动过的几块是完全支持的，也正是推荐的用法。

三、导入术语表（CSV）

术语表是人工成果（3,903 条，其中 3,359 条填过中文名），导入要小心。

格式

Excel 另存为 CSV，第一行是表头，列名认这些（中英文都认）：

列 认得的写法 必需
英文名 英文名 / 英文 / en / id / english / 页面 是
中文名 中文名 / 中文 / zh / chinese / 译名 是
别名 别名 / 别称 / alias / aliases 可选
状态 状态 / status 可选（默认 draft）

例：

英文名,中文名,别名,状态
Kiln,熔炉,炉子,verified
Flame Altar,灵火祭坛,祭坛/圣坛,verified

别名不用单开一列存 —— 库里「别名」本来就是中文名用 、 分隔的若干写法， 导入时自动合并去重。所以 Kiln 存进去就是 熔炉、炉子。

注意

  • Excel 里别名带逗号时会加双引号（"炉子,窑"），解析器认这个，不会把一个别名拆成两列；
  • 旧的无表头 TSV 也还能导（按列位置认，状态在第 5 列）；
  • 同一份文件导两次 = 不产生重复行，以最新导入为准（覆盖）；
  • 保存即生效（词表按版本号自动感知，不用重启）；
  • 入口：管理端 → 知识库 → 词条 → 「导入」。推荐 .xlsx（Excel/WPS 直接编辑，没有编码问题）； .csv / .tsv 仍然收，但中文 Windows 上另存 CSV 容易变成 GBK → 中文乱码，所以导出默认给 xlsx。

四、改已经导进来的内容

两条路，各有适用场景：

想做什么 怎么做
改正文 「文档」面板 → 展开文档 → 该块「编辑」→ 保存（会自动重算这一块的向量）
下架某块 「文档」面板 → 该块「下架」（保留数据，可恢复）
删除某块 「文档」面板 → 该块「删除」（物理删除，不可恢复）
整份下架 「文档」面板 → 文档行「整份下架」
改名字/别名 「词条」面板（词条只管名字，不管正文）
首屏清空重来 「文档」面板 → 「清空全部块」（不可逆，会二次确认）

⚠️ 改正文必须走「文档」面板 —— 因为只有那里会重算向量。 只改文本不重算向量，检索会按旧正文匹配，改了等于没改。

五、验收脚本

界面的自动化验收脚本（需要宿主的前端 dev 或后端在跑）：

node tests/verify-kb-docs-panel.js
# 或指定地址
BASE=http://localhost:8080 node tests/verify-kb-docs-panel.js

它验 12 件事，包括：默认落在「文档」tab、概览数字、预览调的是 preview 而不是 import、 预览里的 id 提醒会显示、确认导入的请求体、展开文档看到块、改正文的请求体、 下架/删除、删除和清空都要弹二次确认、0 console error。

写这个脚本时宿主服务停着，所以它还没被真正跑过；起服务后跑一遍，不过我再修。

六、给外部 AI 的交付要求（一句话版）

按 知识库文档格式规范.html 产出：标题中文、id 英文（页面名-序号）， 每块一个唯一 id，正文翻译成中文，去掉导航/页脚/模板痕迹，保留全部数值与配方。 产出后跑 ./scripts/validate-kb-doc.sh 文件.md，退出码必须是 0。

更新时只给改动过的块即可 —— 没给的那些系统一个都不会动。
