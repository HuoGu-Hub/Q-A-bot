知识库文档格式规范

这份文档给谁看：系统外部负责产出资料的人或 AI。 系统内部只做「符合本规范的文档 → 知识库」，不负责抓取网页、也不负责清洗。 所以：网页怎么变成下面这种文档，是外面的活；本文定义的是交付标准。

不合规的材料可以用校验器当场检查：./scripts/validate-kb-doc.sh 你的文件.md

一、整体结构

一份文档 = 可选的文档头 + 一个或多个块。

<!-- doc
name: Flame Altar
source: wiki
url: https://enshrouded.wiki.gg/wiki/Flame_Altar
tags: Essentials, Stations
-->

=== Flame Altar === <!-- id: flame-altar-0 -->
Flame Altars are respawn points. You can upgrade them…

=== 升级材料 === <!-- id: flame-altar-1 -->
Upgrading requires 5 Shroud Wood and 3 Resin…
  • 一份文档对应一个独立的资料单位（通常是一个网页 / 一个章节 / 一份手册）
  • 块是最小的检索单位。检索命中、送进模型的都是块

二、文档头（可选，但强烈建议）

放在文件最前面，格式固定：

<!-- doc
key: value
key: value
-->
字段 必填 说明
name 必填 文档身份。用于把块归到同一份文档（「文档」面板按它分组、整份下架/清空）
url 强烈建议 原文地址。机器人回答时会把它作为出处给群友，你也要靠它核对
tags 建议 分类标签，逗号分隔。用于板块归类与公开站筛选
source 可选 来源标记（如 wiki / manual / forum）
其他 可选 自定义字段原样保留，不会被丢

文档头里不需要写标题或别名 —— 命名看的是块标题（见下一节）。

导入之后自动发生的事：一个块 = 一个词条

导入时，每个块都会在词条表里占一行（所以不用再单独导术语表）：

词条的「块 id」  = 块的 id（没写 id 就用标题顶替）
词条的「中文名」 = 块标题

于是「知识库 → 词条」就是分块的目录：一份文档有多少块，就多出多少条词条 —— 导一份 147 块的图鉴，就有 147 个词条，每一条对应一个分块。

标题里结尾的 （English） 会被拆成别名。 比如：

=== 深渊之翼斧（Abyssal Wing Axe） === <!-- id: abyssal-wing-axe -->
→  词条：深渊之翼斧、Abyssal Wing Axe

这不是装饰：检索的关键词路判定"命中"靠的是这个词条名出现在群友的问句里， 而群友只会说「深渊之翼斧」这四个字，不会把整条带英文的长标题说出来。

导入时已存在的词条不会被覆盖（只在中文名为空时补齐）—— 人工核对过的名字要改请去「词条」面板。

硬性要求：

  • 首行必须恰好是 <!-- doc（前后空格无所谓，大小写不敏感）
  • 必须有闭合的 -->

⚠️ 最常见的翻车：忘了写 -->。这会让文档头一路往下吃，把后面的正文也当成元数据吞掉 —— 表现为"导入后少了好几块"。校验器会专门报这个。

三、分块分隔符

n*= 标题 n*= <!-- id: xxx -->

3.1 等号个数宽容，但左右必须一样多

写法 结果
= 标题 = ~ ======== 标题 ======== ✅ 都是分隔符
=== 标题 == ✅ 不是分隔符 → 当普通正文
== 标题 ==== ✅ 同上，不是分隔符

3.2 标题

  • 自动去掉前后空格
  • 标题里想出现 =，用反斜杠转义：=== a \= b === → 标题是 a = b
  • 标题可以为空，但那样必须有 id

3.3 id

=== 标题 === <!-- id: flame-altar-0 -->
  • 只允许：英文字母、数字、-（正则 [A-Za-z0-9-]+）
  • 不允许中文、空格、下划线、点、斜杠
  • 可选，但强烈建议写。理由见下面 3.5

3.4 转义

正文里本来就有一行长得像分隔符时，在行首加一个反斜杠：

\=== 这其实是我的正文 ===

导入后这一行的内容会变成 === 这其实是我的正文 ===（反斜杠被吃掉，fmt 正确）。

行首的反斜杠只在"去掉它之后确实是分隔符"时才被吃掉，所以正文里的 Windows 路径（\server\share）之类不受影响。

3.5 ★ 唯一性规则（重要）

规则 违反的后果
key 在同一份文档内必须唯一 致命错误，整份不能导入
标题重复 只提醒，不阻断

key 的定义：有 id 用 id，没有 id 就用标题。

所以：

  • 每个块都写了 id → 标题重复完全没关系（推荐这种）
  • 两个块都没写 id 且标题相同 → key 撞车，致命错误

一个页面被拆成多块时，请给每块不同的 id（如 xxx-0、xxx-1）， 标题保持页面名即可。这是最常见也最推荐的写法。

四、内容要求（清洗规范）

这是知识质量的决定性环节。系统不负责清洗，所以这一步做得好不好，直接决定机器人答得准不准。

4.1 必须做

做 说明
去掉导航、页脚、侧栏、广告、评论区、"相关链接" 这些不是知识，收进来只会抢检索结果
去掉模板/机器痕迹 见下面的反面教材
保留全部事实：数值、配方、材料、位置、掉落、解锁条件 这些是群友真正要问的
一块讲一件事 块是检索单位。一块里混 5 个主题，检索命中后会答非所问

4.2 绝不能做

  • 不要编造。原文没写的，宁可不要这一块，也不要"补全"
  • 不要把多个页面的内容混进一个块

4.3 反面教材（真实例子）

现有语料里有一块长这样（没清干净）：

Absorb：Infobox/Skill: title: Absorb; ID: ABSORB; description: When you suffer
magical damage, you have a 10% chance to generate 1 mana…

Infobox/Skill: title: … ; ID: … 是模板参数，不是人话。 正确的输出应该是：

Absorb is a Warrior skill. When you suffer magical damage, you have a 10%
chance to generate 1 mana for each health point lost. Unlock cost: 3.

4.4 关于长度

  • 单个块建议 40 ~ 1600 字（低于 40 字的块信息量太少，超 1600 字的块检索会变粗）
  • 校验器会提示"有 N 块超过 1600 字"

4.5 语言：正文用中文

已定：外部 AI 负责把内容翻译成中文再产出。

位置 用什么语言 说明
块正文 中文 群友直接看到的就是它
块标题 中文 一个块只讲一件事，标题简明
块 id 英文 稳定标识，不要跟着标题改。约定「英文页面名-序号」，如 flame-altar-0
文档头 url 原文地址 保持原样，不要翻译 URL
文档头 tags 中文 板块/分类标签

id 用英文的理由：它是数据库里的主键。中文标题以后只要改一个字，id 就跟着变的话， 块的身份、以及和术语表的对应关系就全断了。

五、怎么自查（校验器）

./scripts/validate-kb-doc.sh 你的文档.md

输出示例（一份有问题的文档）：

[有问题] kb-doc-bad.md
  文档头 : name=错误示例  url=https://example.com/page  tags=[测试]
  分块   : 3 块，正文共 45 字（平均 15 字/块）
  ✗ 致命问题 1 条：
      第 12 行：id 只能由英文字母、数字和 - 组成，实际是「熔炉」
  ! 提醒 2 条：
      文档头里有不是「key: value」格式的内容：「=== 左右等号不等 ==…」。
      最常见的原因是文档头忘了写 -->，导致它把后面的正文也吃进去了

退出码 0 = 可以导入；1 = 有致命问题，可以直接接进你的自动化流程。

六、常见错误对照表

错误 校验器怎么说 怎么改
左右等号不一样 === 标题 == 不报错（当正文）→ 表现为"少了一块" 数一遍两边的 =
id 里有中文 id 只能由英文字母、数字和 - 组成，实际是「熔炉」 换成 kiln 这种
两个块没 id 且同名 key「X」重复了…这个块没写 id，是用标题当的身份 给每块补上不同 id
两块 id 相同 key「X」重复了（第 N 行已用过） 改掉其中一个
忘了写 --> 文档头里有不是「key: value」格式的内容… 补上闭合
整份没有分隔符 整份文档里没有找到任何分块分隔符 检查分隔符写法
块的正文是空的 第 N 行：「X」这一块正文是空的 删掉空块或补内容
开头有不属于任何块的文字 第一个分隔符之前有 N 行内容 要么删掉，要么放进一个块里

七、完整的合规样例

见仓库里这两份：

文件 用途
docs/samples/kb-doc-ok.md 合规样例（格式示范；内容是旧英文语料，实际产出的语言以中文为准）
docs/samples/kb-doc-bad.md 违规样例（故意犯错，用来看校验器报什么）

一份中文文档该长这样：

<!-- doc
name: 灵火祭坛
url: https://enshrouded.wiki.gg/wiki/Flame_Altar
tags: 基础, 据点
-->

=== 灵火祭坛 === <!-- id: flame-altar-0 -->
灵火祭坛是复活点。死亡后会在最近的祭坛复活。

=== 升级材料 === <!-- id: flame-altar-1 -->
升级需要 5 个瘴气木和 3 个树脂。

注意：标题中文、id 英文。

附：可直接粘贴给外部 AI 的指令

你要把网页内容整理成知识库文档，格式要求如下：

  1. 文件开头写文档头（若有原文地址必须给 url）：
    <!-- doc
name: <页面名>
source: wiki
url: <原文地址>
tags: <标签1, 标签2>
-->
    注意 必须有闭合的 -->。
  2. 正文按块写，每块以分隔符开头，每块给一个唯一的 id：
    === 页面名 === <!-- id: 页面名英文-序号 -->
    id 只能用英文字母、数字和 -。分隔符两边的 = 数量要一样多。
  3. 一个块只讲一件事，每块 40~1600 字。
  4. 内容要求：
    • 去掉导航、页脚、广告、评论区、相关链接
    • 去掉模板机器痕迹，例如不要出现 Infobox/Skill: title: X; ID: Y; 这种
    • 数值、配方、材料、位置、掉落 一个都不能漏
    • 不要编造原文没有的内容
  5. 正文里如果本来就有像 === 标题 === 的行，在该行行首加一个反斜杠转义。
  6. 产出后用 ./scripts/validate-kb-doc.sh 文件.md 自查，退出码必须是 0。
