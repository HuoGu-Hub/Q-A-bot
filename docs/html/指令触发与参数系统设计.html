指令系统 · 触发与参数重构

从斜杠到 @命令-值

现有指令只能表达「命令」和「一整串参数」。要记录一件定时发送的事，群友得把事件和时间揉成一坨文本，机器人没法知道哪段是时间。这一版把命令拆成「命令名 + 声明式参数表」，让 @ 直接带上结构化取值。

一句话结论

触发从「/ 前缀」扩成两种形态：斜杠形态保持原样，@ 机器人 + 命令名 + 破折号分隔的值是新增形态。命令在库里声明自己的参数表，参数按类型解析、按名称取用，解析失败就回一句用法提示，绝不猜。动作类命令不调模型，直接交给一个可注册的执行器；定时任务落一张表，由一个扫描器到点经同一个出站口发出。

现有系统卡在哪

不是缺功能，是四个边界把新用法挡住了。

现状导致什么
只认 / 前缀@ 了机器人之后还得再打斜杠，手机端两步操作，群友记不住。
参数只有一整串文本{args} 与 {args.N} 按空格切。事件里本来就有空格，切完就对不上号。
只有 template 与 agent 两类两类都只会「回一句话」，没法写库、没法定时、没法撤销。
min_role 只存不判字段在库里、在后台表单里，代码里没有任何一处读它。删除别人的任务没有权限概念。

前三条是能力缺口，第四条是既有漏洞，这次一并补上。

新触发模型

一条群消息要变成指令，依次过四道闸。顺序不能换：先准入，再 @，再认形态，最后查表。

  消息事件
     │
     ├─ ① 准入          黑名单 / 私聊策略        不过 → 丢弃，与普通消息同一份判定
     ├─ ② @ 判定        群里是否 @ 了机器人    开关 require-mention
     ├─ ③ 形态识别      斜杠形态 → 取首词
     │                  破折号形态 → 取第一个 - 之前的词
     └─ ④ 查表          命令名落在指令表里才算命中
                        不命中 → 交回普通问答，不是错误

两种形态

形态写法值怎么分状态
斜杠/记录 打本集合 20:00空白分，最后一段吃剩下的保留
破折号@机器人 记录-打本集合-20:00破折号分，值里可以有空格新增

两种形态进同一个参数解析器，只是分隔符不同。破折号形态额外接受全角 － 与 —，中文输入法打不出半角时不会卡住。

为什么不会误触发

破折号形态看起来比斜杠宽松，实际上更严：命令名必须在指令表里。群里聊「今天-明天」不会命中，因为「今天」不是命令。真正被放开的是「触发词后面接东西」，而那正是我们要的。

还有一条隐含约束：只有声明了参数表的命令才支持破折号形态。话术类老命令仍旧只认斜杠，行为一个字节都不变。

@ 是闸门，不是装饰。破折号形态依赖 @ 把自己和正常聊天分开。若关掉 require-mention，「记录」这个词就会变成保留词，群友再也不能用「记录-xxx」说别的事。所以这个开关在破折号形态下建议保持开启，配置页会给出提示。

参数：声明式参数表

命令不再靠调用方约定参数顺序，而是在库里声明。参数表是命令的一部分，后台可编辑，可预览。

字段含义例
name参数名，模板里用 {arg.name} 取事件
type取值类型text
required缺了是否算解析失败true
default可选参数的默认值30
maxChars文本长度上限200
example用法提示里展示的样例打本集合

四种类型

类型接受什么归一成什么
text任意文本，超长按 maxChars 截断原样字符串
int十进制整数，允许前置负号long
moment20:00、明天20:00、10-18 20:00、3小时后东八区的 Instant
enum参数表里列出的候选值，可给别名规范值

时间只认 AppTime 那一个口径。整条链路——解析、落库、展示、扫描——都用东八区，不引入第二套时区换算。

切分规则

破折号天然会和日期、内容里的连字符打架。规则只有一句：类型化参数从右往左锚定，文本参数吃剩下的。

  参数表：事件(text) · 时间(moment)
  输入：  打本集合-第3关-20:00
  结果：  事件 = 打本集合-第3关
          时间 = 今天 20:00

实现上是有界回溯，参数上限 4 段：文本参数先按最短尝试，类型化参数必须解析成功；某一档不通过就多给文本一段再试，直到全部落位。上面这例只有把前三段整体交给事件、最后一段留给时间才全部通过。

仍有歧义时给引号逃生口：记录-"打本-第3关"-20:00。双引号、中文引号、书名号都认，引号内的分隔符不参与切分。

输入参数表结果
记录-打本-20:00事件 text · 时间 moment事件=打本，时间=今天 20:00
记录-打本-第3关-20:00同上事件=打本-第3关，时间=20:00
记录-打本-10-18 20:00同上事件=打本，时间=10 月 18 日 20:00
记录-打本同上缺时间，回用法提示
记录-打本-25:99同上时间不合法，回用法提示并指出是哪一段
删除-3编号 int编号=3

失败要说清哪一段不对

解析失败不能只回「格式错误」，群友不知道改哪里。回执固定三段：哪一个参数、期望什么、完整用法。

  没看懂「时间」：25:99 不是有效时间。
  用法：@机器人 记录-事件内容-时间
  例：  @机器人 记录-打本集合-20:00

动作：第三类命令

命令类型从两类扩成三类。选择依据是「这次触发要不要花钱、要不要落库」。

kind做什么走 Guard 与预算例
template渲染模板秒回不走/help
agent参数当问题交给模型走/联网 今天什么版本
action交给注册的执行器，写库或查库不走@机器人 记录-…-20:00

动作用注册表分发，不写 switch (command.action())。每个动作是一个类，实现同一个接口：声明自己的参数表与用法，执行时拿到已经解析好的参数和上下文，返回一句回执。新增一个功能就是新增一个类，不改分派代码。

  interface CommandAction {
      String id();                 // schedule.create
      List<ParamSpec> params();     // 它的参数表，种子写库时用
      String usage();              // 没带参数时回的话
      String execute(ActionContext ctx, CommandArgs args);
  }

库里存的是动作 id 而不是类名。动作被删掉之后，那条指令在匹配阶段就当作停用并记一条告警日志，不会在线上抛 ClassNotFound。

定时任务：从记下到发出

三个内置动作组成一条闭环。它们都是 builtin，不可删除，但回执文案可在后台改。

命令动作参数回执
记录schedule.create事件 text · 时间 moment已记下 #3：今天 20:00 在本群发送「打本集合」
任务schedule.list无本群待发 #3 今天 20:00 打本集合
删除schedule.delete编号 int已撤销 #3

任务表

  bot_schedule
    id           INTEGER PK        // 就是回执里的编号
    group_id     INTEGER           // 0 = 私聊
    user_id      INTEGER           // 创建者，删除权限的依据
    content      TEXT              // 到点要发的那句话
    fire_at      TEXT              // ISO 时刻，UTC 存盘
    status       TEXT              // pending / sending / sent / failed / expired / canceled
    attempts     INTEGER
    last_error   TEXT
    created_at   TEXT
    sent_at      TEXT

索引建在 (status, fire_at) 上，扫描只走这一条。

扫描器要定的五件事

问题决定理由
多久扫一次10 秒，首次延迟 15 秒群聊提醒差十秒能接受，扫太勤只是空转。
会不会重复发先 UPDATE … WHERE status='pending'，更新到 1 行才发同一行只能被一个 tick 抢到。多实例也没问题，只要共用同一个库。
停机错过了怎么办30 分钟内补发；超过标记 expired，不补半夜重启后补发一条「下午三点集合」只会让人困惑。
发送失败怎么办重试 3 次，间隔退避；仍失败标 failed协议端短暂掉线不该把任务丢掉，但也不能无限重试。
线程池显式把 spring.task.scheduling.pool.size 调到 2Spring 默认调度池只有一个线程，别的定时任务会被这个 10 秒 tick 挤在后面。

发送走哪条路

扫描器不碰协议客户端，只调出站发送器。群聊走 sendToGroup，私聊需要新增一个 sendToPrivate，两者共用同一段出站过滤、分片与节流。定时发送不能成为绕过内容过滤的侧门，这是铁律②的直接后果。

删除：编号、权限、回执

删除按编号，不按内容匹配。内容匹配会误删——两句「打本集合」分不清是哪条。

谁能删判定
创建者本人task.user_id == 触发者
群主与群管事件里的 sender.role 是 owner 或 admin
其他群友拒绝，回「#3 不是你建的」
别的群查不到。任务是群内资产，跨群不可见

删除是软删除：状态改成 canceled，保留是谁、何时撤的。列表只显示 pending 与 sending，后台能看到全部。

权限判定统一走 min_role，把「只存不判」那个缺口补上。角色由路由层归一化成 owner / admin / member / none 放进上下文，动作层不解析 OneBot 的 JSON。

组件与依赖

新代码落在 command 包，持久化落 persistence。有三条既有护栏会直接约束实现方式：

  • 业务包不得依赖 config —— 扫描器与动作的配置走 CommandPolicy 那样的只读接口，由 config 侧实现，不在业务包里 import 配置类。
  • 只有 outbound 与 router 能碰 OneBotApiClient —— 扫描器只持有 OutboundSender。
  • 持久化之外不得出现 java.sql —— 新表的所有 SQL 进 ScheduleRepository。

验收清单

  • 群里不 @ 不触发；@ 了但命令名不在表里，当普通聊天。
  • 打本-第3关-20:00 切出的事件里保留连字符。
  • 25:99、缺时间、多出三段，三种失败都给出具体是哪一段。
  • 老模板里的 {args.1} 行为不变。
  • 跨群删除查不到；非创建者删除被拒；群管可以删。
  • 停机 10 分钟后重启，补发；停机 2 小时后重启，标记过期不补。
  • 定时内容里出现敏感词时被出站过滤拦下，与即时回复同一套判定。

风险

风险处置
定时发送变成骚扰工具每人待发上限 5 条、内容 200 字、沿用独立限流；到点仍走出站过滤。后续可加免打扰时段。
SQLite 写锁任务写入是单行插入，量级是每人每天几条。扫描每 10 秒读一次，冲突概率可以忽略。
多实例重复发送状态位 CAS 已经兜住；部署文档写明当前按单实例设计。
时间语义歧义20:00 若已过则顺延到明天，并在回执里写明「明天」，不让群友自己猜。

需要你拍板的三件事

1. 要不要保留斜杠形态。建议保留。老群友的习惯、后台里已有的指令、{args} 模板都依赖它，而且零成本。

2. 命令名用中文还是英文。建议中文：记录、任务、删除。破折号形态下英文命令名和正常英文聊天更难区分。

3. 定时任务要不要开放到私聊。建议先只开群聊。私聊没有群管的第二双眼睛，滥用成本更低；表结构留了 group_id=0，以后放开不用迁移。
