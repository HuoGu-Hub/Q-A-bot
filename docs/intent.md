# 意图路由

意图路由只回答两个问题：这一轮要不要检索知识库，这一轮是不是在纠正上一轮。回答语气与结构仍由 `system.md` 决定。

## 1. 判定顺序

1. 出现“我的意思是”“我是说”等自我修正，放弃判定，按默认链路处理。
2. 命中纠正词，标记为 `CORRECT`。
3. 命中边界外请求，标记为 `OUT_OF_SCOPE`。
4. 命中关于机器人自身的元问题，标记为 `META`。
5. 命中完整社交称呼或整活句式，标记为 `SOCIAL`。
6. 其余全部为 `DEFAULT`。

| 类型 | 是否检索 | 行为 |
|---|---|---|
| `SOCIAL` | 否 | 一句话回应，不长篇解释 |
| `META` | 否 | 只介绍机器人自身能力与边界 |
| `OUT_OF_SCOPE` | 否 | 直接说明做不到，不调用工具 |
| `CORRECT` | 是 | 带上最近一轮问答，只改被指出的部分 |
| `DEFAULT` | 是 | 与未接入意图路由时完全一致 |

## 2. 规则边界

- 只认高置信词形，不做语义分类器。
- 社交类要求完整称呼，例如“叫我主人”；只出现“主人”不判定。
- 元问题要求以“你是”“你有”等开头；只出现“你会”不判定。
- 自我修正优先于其他规则。半句改口时，按上半句判必然错，因此直接放弃。
- `IntentPlanner` 保证不抛异常。判定失败、配置缺失、规则异常都回退 `DEFAULT`，不能因为判定挂掉一条正常提问。

## 3. 会话记忆

纠正是唯一需要上下文的场景。记忆保存在 `qa_turn`：

| 项 | 值 |
|---|---|
| 范围 | 按群 + 用户隔离 |
| 条数 | 最近 3 轮 |
| 时间窗 | 30 分钟 |
| 回答摘要 | 前 60 字 |
| 保留 | 7 天 |
| 写失败 | 当作没有记忆，不影响回答 |

纠正时把上一轮的问题与回答摘要放进提示词，要求只改被指出的部分，不整段重答。普通提问不带历史，避免历史污染和消息变长。

## 4. 回答契约

`system.md` 把回答分为三类：

| 类型 | 约束 |
|---|---|
| 事实类 | 是什么、在哪、怎么获得、多少级；只用资料中的事实，资料没有就说明没查到 |
| 建议类 | 推荐、搭配、评价、哪个强；先写资料能支撑的事实，再给结论与排序 |
| 社交类 | 卖萌、吐槽、玩笑、身份问题；一句话，默认不查资料，可在配置里按类关掉 |

建议类允许给结论，但结论必须与资料事实分开。资料不足时说明“资料里能确定的是 X，剩下的是我的看法”，不要用“资料里没查到”收尾。

## 5. 配置

| 键 | 默认 | 作用 |
|---|---|---|
| `app.intent.enabled` | `true` | 总开关 |
| `app.intent.skip-social` | `true` | 社交整活跳过检索 |
| `app.intent.skip-meta` | `true` | 关于机器人自己跳过检索 |
| `app.intent.skip-out-of-scope` | `true` | 做不到的请求跳过检索 |
| `app.intent.correction` | `true` | 识别对上一轮的纠正 |
| `app.intent.recent-turns` | `3` | 读取最近几轮 |
| `app.intent.recent-minutes` | `30` | 最近几轮的时间窗 |

全部热生效。三类跳过检索的开关互不影响：关掉哪一类，哪一类就照常检索。旧的 `app.intent.skip-retrieval` 已拆成三个键；升级后按类设置。关闭 `enabled` 等价于回到默认检索链路。

## 6. 统计

- 日志前缀为 `[INTENT]`，记录类型、是否检索、是否纠正与理由。
- 跳过检索的请求不计入“检索未命中”，否则会拉低命中率。
- `qa_turn.corrected` 标记上一轮被纠正，用于事后统计纠正率，不参与实时决策。

## 7. 概率回复

关闭「群里必须 @」后，触发判定按三档工作：@、正文昵称、引用机器人直通；疑问按 p 回复；闲聊从 p=0.5 起逐步解禁。噪音与纯图不参与。主动回复记 `auto`，不计入提问，也不参与追问检测。

配置在 `app.reply.*`，只在 `enabled-groups` 列出的群里生效。完整设计与默认值见 [概率回复方案](html/概率回复方案.html)。
