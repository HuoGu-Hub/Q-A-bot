Ops / Cheatsheet

服务器运维命令速查

Debian 12/13 与 systemd 环境，含 qqbot 服务、Nginx、Docker 的日常操作。点命令即复制。

巡检系统资源进程服务磁盘 日志排障网络端口NginxDocker 软件包用户权限定时与时间传输备份 危险命令

先看这个顺序：出事时按「负载 → 内存 → 磁盘 → 日志 → 端口」查，九成问题在前三步就能定位。

两个习惯：改配置前先 cp 文件 文件.bak；重启服务前先 systemctl status 看清状态。

一个原则：能用 systemctl restart 就不要 kill -9，systemd 会帮你收拾干净。

00日常巡检

每天登录先跑这五条，一分钟看完机器状态。

  • uptime跑了多久、负载 1/5/15 分钟
  • free -h内存与 swap，看 available 那列
  • df -hT各分区使用率，超 85% 要处理
  • systemctl --failed启动失败的服务
  • ss -tulnp当前监听端口与对应进程
  • last -n 10最近登录记录，发现陌生 IP 立刻查

01系统与资源

  • hostnamectl主机名、系统版本、内核、虚拟化
  • cat /etc/os-release发行版与版本号
  • uname -r内核版本
  • nprocCPU 核数，判断负载是否真高
  • top实时进程，按 1 看各核，按 M 按内存排
  • top -b -n1 | head -20一次性快照，适合贴给别人看
  • vmstat 1 5CPU、内存、IO、上下文切换每秒采样
  • iostat -xz 1 5磁盘 IO，看 %util 与 await
  • pidstat -d 1哪个进程在读写磁盘
  • sar -u 1 5历史 CPU，事后复盘用
  • dmesg -T | tail -40内核日志，带可读时间
  • dmesg -T | grep -i "out of memory"查有没有进程被 OOM 杀过
  • ulimit -n当前会话的文件句柄上限
  • lsof | wc -l系统打开的句柄总数

sysstat 系列命令若提示找不到，装一下：sudo apt install -y sysstat。

02进程与服务

  • ps aux --sort=-%cpu | headCPU 占用最高的进程
  • ps -eo pid,user,%cpu,%mem,etime,cmd --sort=-%mem | head内存排行，带运行时长
  • pgrep -af qqbot按名字查进程与完整命令行
  • pstree -p 1234看进程父子关系，查重复启动
  • top -Hp 1234看单个进程内部哪个线程吃 CPU
  • kill 1234发 TERM，让程序自己收尾
  • kill -9 1234最后手段，可能丢数据、留脏锁
  • systemctl status qqbot状态、最近日志、启动命令
  • systemctl restart qqbot重启业务服务
  • systemctl reload nginx平滑重载配置，不断连接
  • systemctl enable --now qqbot设开机自启并立刻启动
  • systemctl cat qqbot看 unit 文件内容与路径
  • systemctl daemon-reload改过 unit 文件后必须执行
  • systemctl list-timers系统定时任务与上次执行时间
  • journalctl -u qqbot -f实时跟服务日志
  • journalctl -u qqbot -n 200 --no-pager看最近 200 行，不进入分页器

03磁盘与空间

  • df -hT分区、文件系统类型、使用率
  • df -iinode 使用率，满了一样写不进文件
  • du -sh /var/* | sort -h/var 下各目录大小排序
  • du -h --max-depth=1 / | sort -h | tail -12全盘找大户
  • find / -xdev -type f -size +500M -exec ls -lh {} + | sort -k5 -h找大于 500M 的文件
  • find /var/log -type f -mtime +30 -ls只列出 30 天前的日志，先看再删
  • lsof +L1被删除但仍占空间的文件，重启对应服务才释放
  • truncate -s 0 /var/log/app.log清空日志且保留文件与句柄
  • lsblk -f块设备、文件系统、挂载点
  • findmnt /data确认某个目录挂在哪块盘上
  • du -sh /opt/qqbot/* 2>/dev/null | sort -h业务目录体积分布

04日志与排障

  • tail -F /var/log/nginx/error.log实时跟日志，日志轮转会自己续上
  • tail -n 300 app.log | grep -i -E "error|exception"只看错误行
  • grep -rn "listen" /etc/nginx --include="*.conf"按关键词搜配置
  • zgrep -i error /var/log/syslog.1.gz搜压缩过的旧日志
  • journalctl --since "1 hour ago" -p warning一小时内警告及以上
  • journalctl -k | tail -50内核日志，等同 dmesg
  • journalctl --disk-usage日志占了多少空间
  • journalctl --vacuum-time=7d只保留 7 天日志
  • awk '{print $1}' access.log | sort | uniq -c | sort -rn | head访问量最大的 IP
  • grep -c " 500 " access.log统计 500 错误条数
  • sed -n '100,140p' app.log看指定行区间
  • less +F app.log跟日志同时能往回翻，Ctrl+C 退出跟随

05网络与端口

  • ip a网卡与 IP 地址
  • ip route默认网关与路由表
  • ss -tulnp监听中的 TCP/UDP 与进程
  • ss -tnp state established | head -20已建立的连接
  • ss -s连接数汇总，查 TIME_WAIT 堆积
  • lsof -i :8080谁占了 8080
  • fuser -n tcp 8080同上，输出 PID
  • netstat -tunlp老系统习惯，需装 net-tools
  • ping -c 4 1.1.1.1测基础连通
  • mtr -rw 1.1.1.1链路每一跳的丢包与延迟
  • nc -zv example.com 443测端口通不通，不依赖 telnet
  • curl -I -m 5 https://example.com只看响应头，带超时
  • curl -o /dev/null -s -w '%{http_code} %{time_total}s\n' https://example.com只看状态码与耗时
  • dig +short example.com解析结果
  • tcpdump -i any -nn port 80 -c 50抓 50 个包，只读不改
  • iptables -L -n -v --line-numbers看防火墙规则，Docker 会插自己的链
  • which iptables && nft list ruleset | head -40Debian 12 起默认 nftables 后端
  • hostname -I所有本机 IP，一行输出

06Nginx

  • nginx -t改完配置先测语法，再 reload
  • nginx -T | grep -n "server_name"导出合并后的完整配置
  • systemctl reload nginx平滑生效
  • tail -F /var/log/nginx/error.log排查 502/504 首先看这里
  • awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn按状态码统计分布
  • awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -20访问最多的 URL
  • curl -H "Host: your.domain" http://127.0.0.1/health绕过 DNS 直连本机测站点
  • systemctl status nginx --no-pager -l看是否有端口冲突或权限报错

项目配置在 deploy/nginx/*.conf，改完先 nginx -t 再 reload，失败时旧进程仍在跑，不会断服。

07Docker 与 NapCat

  • docker ps -a容器列表，含已退出的
  • docker compose ps在 deploy 目录看编排状态
  • docker compose logs -f --tail=100实时日志
  • docker compose restart重启编排内所有容器
  • docker compose up -d拉配置后重建启动
  • docker stats --no-stream各容器 CPU/内存占用快照
  • docker exec -it napcat bash进容器排查，名字以 docker ps 为准
  • docker inspect --format '{{.State.Health.Status}}' napcat看健康检查状态
  • docker system df镜像、容器、卷各占多少
  • docker image prune -a清理无用镜像，先看 df 再动手
  • docker compose down && docker compose up -d配置大改后重建

08软件包与依赖

  • sudo apt update刷新软件源索引
  • sudo apt upgrade -y升级已装包，不删不换
  • sudo apt install -y htop sysstat装常用工具
  • apt list --installed | grep nginx确认装了什么版本
  • dpkg -L nginx这个包装了哪些文件
  • apt-cache policy nginx已装版本与可升级版本
  • sudo apt autoremove -y清理不再需要的依赖
  • dpkg -S /usr/sbin/nginx反查文件属于哪个包
  • java -version确认 JRE 版本，项目要求 17 以上

09用户与权限

  • id当前用户与所属组
  • who谁在线，从哪个 IP 来
  • sudo -l当前用户能免密执行哪些命令
  • useradd -m -s /bin/bash dev建用户并给家目录与 shell
  • usermod -aG docker dev追加组，需重新登录生效
  • chown -R www-data:www-data /data/www改属主属组
  • chmod 750 /data/www属主 rwx，组 r-x，其他无权限
  • chmod -R u+rwX,go-w /data/www大写 X 只给目录加执行位
  • lastb | head -20失败的登录尝试，判断是否在被爆破
  • grep -c "Failed password" /var/log/auth.log密码爆破次数统计

10定时任务与时间

  • crontab -l当前用户的定时任务
  • crontab -e编辑，格式 分 时 日 月 周
  • systemctl list-timers --all系统级定时器，比 cron 更好排查
  • timedatectl时区、NTP 同步状态
  • sudo timedatectl set-timezone Asia/Shanghai改时区，日志时间才对得上
  • chronyc sources -v时间源同步情况
  • date -d @1700000000时间戳转可读时间，对着日志查

cron 不执行时先查两件事：脚本里用绝对路径；把输出重定向到文件再判断，例如 * * * * * /opt/x.sh >> /tmp/x.log 2>&1。

11传输、备份与终端

  • tar czf backup-$(date +%F).tar.gz /etc/nginx打包带日期
  • tar xzf backup.tar.gz -C /tmp解包到指定目录
  • rsync -avz --progress src/ user@host:/dst/增量同步，末尾斜杠表示同步目录内容
  • rsync -avz --delete src/ /dst/目标多余文件会被删，先加 --dry-run 跑一遍
  • scp -P 2222 app.jar user@host:/opt/注意端口是大写 P
  • sha256sum app.jar上传后校验文件完整性
  • nohup ./app.sh > run.log 2>&1 &临时后台跑，正式环境用 systemd
  • tmux new -s ops会话保持，断线不中断任务
  • tmux a -t ops重新接上会话
  • history | tail -30刚敲过的命令
  • echo $HISTTIMEFORMAT空则执行 export HISTTIMEFORMAT='%F %T ' 让 history 带时间

WindTerm 自带 SFTP 面板，拖拽即可上传下载，不必敲 scp；长时间任务放在 tmux 里跑，关掉窗口也不受影响。

12危险命令清单

以下命令执行前，先用 ls 或 --dry-run 确认目标路径，不要凭记忆敲。

  • rm -rf /path先 ls 同路径，路径变量为空会变成删根
  • find / -name "*.log" -delete必须带 -mtime 条件，否则会把正在用的日志删掉
  • rsync --delete先 --dry-run，源目颠倒会清空目标
  • chmod -R 777 /权限全开，等于放弃安全边界
  • kill -9 <pid>systemd 管的服务用 restart，否则会被自动拉起又冲突
  • iptables -F清空规则，远程操作可能直接断连
  • dd if=... of=/dev/sdX写错设备名即毁盘
  • reboot先 w 看有没有人在线，再 sync 落盘

13快速巡检脚本

存成 /opt/check.sh，chmod +x 后随时跑，一次看完全貌。

#!/bin/bash
echo "== 时间与负载 =="; date; uptime
echo "== 内存 =="; free -h
echo "== 磁盘 >80% =="; df -hT | awk 'NR==1 || $5+0>80'
echo "== inode >80% =="; df -i | awk 'NR==1 || $5+0>80'
echo "== 失败的服务 =="; systemctl --failed --no-pager
echo "== CPU Top5 =="; ps -eo pcpu,pid,user,cmd --sort=-pcpu | head -6
echo "== MEM Top5 =="; ps -eo pmem,pid,user,cmd --sort=-pmem | head -6
echo "== 监听端口 =="; ss -tulnp | head -20
echo "== OOM 记录 =="; dmesg -T | grep -i "out of memory" | tail -5
echo "== 最近登录 =="; last -n 5

排查口诀

负载高 → 看 CPU 还是 IO：top 里 wa 高就是磁盘，us 高才是计算。
内存告急 → free -h 看 available，再看 ps --sort=-%mem。
磁盘满 → df -hT 定位分区，du 找目录，lsof +L1 抓被删未释放的文件。
服务起不来 → systemctl status 看退出码，journalctl -u 看原因，先看端口有没有被占。
