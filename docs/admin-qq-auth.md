# 后台 QQ 验证码登录

后台不再使用邮箱/SMTP。账号用**用户名或 QQ 号 + 密码**登录，新设备再收一条 QQ 私聊验证码。

## 前置条件

- 机器人能私聊每个后台用户的 QQ。
- 用户先添加 bot 为好友。
- 第一个管理员的 QQ 写在 `.env` 的 `ADMIN_QQ`。

`ADMIN_QQ` 只在数据库还没有任何账号时生效。已有 `admin` 账号时改它不会改库，需要在后台首次登录后绑定。

## 账号创建

已有管理员 `qq1` 给 `qq2` 开账号：

~~~text
1. qq2 先添加 bot 为好友
2. qq1 登录后台 → 账号 → 新增账号
3. 填用户名、昵称、QQ 号、初始密码、角色
4. 系统给 qq2 发欢迎消息
   - 发不出去 → 注册中止
5. 系统给 qq1 发 6 位验证码
6. qq1 填码
7. 账号创建成功，再通知 qq2
~~~

为什么要有 qq1 的码：证明是管理员本人在操作，不是别人拿了他的会话乱建号。

## 第一次登录

~~~text
用户名 + 初始密码
→ 系统给绑定的 QQ 发验证码
→ 填码
→ 登录成功
~~~

如果账号还没有 QQ，会先进入“绑定 QQ”页，绑定成功前其他接口一律返回：

~~~json
{"error":"请先绑定 QQ","code":"QQ_BIND_REQUIRED"}
~~~

## 日常登录

~~~text
用户名或 QQ 号 + 密码
  ├─ 这台设备在信任期 → 直接进
  └─ 新设备/信任过期 → QQ 私聊验证码 → 填码
~~~

- 会话 7 天。
- 信任设备绝对 30 天、闲置 7 天。
- 信任设备只免验证码，不免密码。
- 改密、退出所有设备时撤销信任设备。

## 安全规则

- 验证码 6 位，5 分钟过期，一次性。
- 只存哈希，不写日志。
- 同一账号同一用途 60 秒冷却，每小时最多 5 条。
- 验证码只走私聊，绝不发群。
- QQ 号唯一，一个 QQ 只能绑一个后台账号。
- 改 QQ 必须用当前 QQ 收码。
- 没有管理员重置、没有恢复码、没有 CLI 绕过。

## 故障边界

- bot 挂了：后台登录和注册都停。这是无邮箱、无后门的必然结果。
- QQ 没加 bot 好友：验证码发不出去，注册/登录会失败。
- QQ 被风控：等恢复或换绑；换绑也需要当前 QQ 收码。
- SMTP 不再依赖，邮件故障不影响后台。

## 上线顺序

1. `.env` 配 `ADMIN_QQ`，重启。
2. 确认 bot 能私聊这个 QQ。
3. 用 `ADMIN_PASSWORD` 登录，收 QQ 码，完成绑定。
4. 进入账号页，给其他人建账号；对方先加 bot 好友。
5. 所有人首次登录后，确认 `qq_verified=1`。
6. 观察 `admin_audit` 里的 `qq-bind-ok`、`user-create`、`login-qq-ok`。

## 数据表

- `admin_user.qq`、`qq_verified`
- `admin_qq_code`：验证码哈希、challenge、过期时间、尝试次数
- `admin_trusted_device`：设备 token 哈希、最后使用时间、绝对过期
