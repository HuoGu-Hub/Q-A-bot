# 安全模型

## 1. 信任边界

| 边界 | 入口 | 控制 |
|---|---|---|
| 公网 → 公开站 | Nginx 443 | TLS、限流、安全响应头、公开 DTO |
| 公网 → 管理后台 | Nginx 443 | 密码、QQ 验证码、角色、会话、Origin 校验 |
| NapCat → 应用 | `/onebot/**` | 共享 Token、HMAC 或 Bearer、请求体上限 |
| 应用 → NapCat | `127.0.0.1:3000` | Bearer Token，仅出站 |
| 应用 → 外部服务 | 模型、向量、wiki | TLS、超时、地址校验、调用预算 |
| 应用 → 本地数据 | SQLite、图片、瓦片 | 单进程、路径守卫、目录隔离 |

应用监听 `0.0.0.0:8080`，但 8080 只能由云安全组和主机防火墙限制为 Docker 网段与回环访问。公网只开放 80 与 443。

## 2. 身份与授权

后台账号保存在 `admin_user`，角色分三级：

| 角色 | 权限 |
|---|---|
| `viewer` | 只读：统计、知识库、日志 |
| `editor` | 编辑：知识库、命令、页面、地图、公告 |
| `admin` | 全部权限，含账号管理与系统设置 |

- 登录使用用户名或 QQ 号加密码；新设备再收一条 QQ 私聊验证码。
- 验证码 6 位、5 分钟过期、一次性，只存哈希，同一账号有冷却与每日上限。
- 信任设备只免验证码，不免密码；绝对 30 天、闲置 7 天。
- 会话 Cookie 带 `HttpOnly`、`Secure`、`Path=/admin`、`SameSite=Strict`；默认 24 小时，可由 `ADMIN_SESSION_HOURS` 调整。
- 写操作校验 `Origin` 与 `Sec-Fetch-Site`。
- 账号、登录、改密、权限变更写入 `admin_audit`。

## 3. 入站

- `OneBotAuthFilter` 校验 `x-signature: sha1=...`，兼容手工测试的 `Authorization: Bearer`。
- 未配置 `ONEBOT_TOKEN` 时拒绝全部事件，不放行。
- 请求体上限 1 MB，与 Nginx 限制一致。
- Nginx 对 `/onebot/event` 单独限制来源，只允许 Docker 网段与回环；公网不能直连 8080。
- NapCat 的 3000、3001、6099 只绑定回环，WebUI 通过 SSH 隧道访问。

## 4. 数据保护

- 聊天蒸馏默认关闭；开启必须显式填写群白名单。
- 原始消息默认保留 90 天，聊天图片 30 天，每天清理一次。
- 能存摘要就不存原文的地方不重复保存；问答原文按保留期清理，统计表长期保留。
- 日志页脱敏；文件与 journal 权限应为 600。
- 数据库、轮播图、语音、知识库图片与配置定期备份；数据库备份使用一致性快照，不直接复制正在写入的 SQLite 文件。
- 备份应异地保存，并至少做一次恢复演练。

## 5. 外联与媒体

- 图片下载只允许公网 http 与 https，拒绝回环、站点内网、链路本地、组播、CGNAT 地址。
- 下载有超时与大小上限，响应必须是图片类型。
- 图片、知识库、聊天、语音、瓦片目录互不嵌套，`MediaStorageGuard` 在启动时拒绝危险配置。
- 模型与向量 Key 只从环境变量或本地覆盖文件读取，不写入仓库。
- CI 运行 `scripts/secret-scan.sh` 与前端依赖审计。

## 6. 成本与可用性

- Guard 五层在调用模型前拦截：准入、触发、限流、内容闸门、入站词。
- 概率回复只在显式群白名单里生效；@、正文昵称、引用机器人直通，主动接话默认 p=0；固定话术对插话降级为静默。
- 用户、群、全局三级每日预算，可再设 token 上限。
- 问答池与命令池分离，队列满或排队超时直接失败，不拖垮进程。
- 公开接口、后台登录、事件入口分别限流。
- 出站有过滤、分片、发送节奏与合并转发。

## 7. 上线验收

| 检查 | 通过标准 |
|---|---|
| 事件入口 | 无 Token 或错误 Token 被拒绝；正确 Token 返回 204 |
| 入口网络 | 公网不能直连 8080；Nginx 只允许 Docker 网段访问 `/onebot/event` |
| 后台路径 | 编辑账号访问账号管理接口返回 403 或 404，审计有记录 |
| 聊天采集 | 首次启动显示未开启，或只采集显式群号 |
| 保留期 | 设为 1 天后，旧消息与图片被清理 |
| 跨群删除 | A 群删除 B 群记录被拒绝 |
| Cookie | 登录响应含 `Secure; HttpOnly; SameSite` |
| 改密 | 改密后旧会话立即失效 |
| 日志 | 文件与 journal 中搜不到完整 QQ 号与消息正文 |
| 备份 | 备份通过 `quick_check`，恢复后能启动 |
| 证书 | TLS 1.2 以上，证书剩余有效期大于 30 天 |
| 依赖 | 无已知 Critical CVE，NapCat 镜像固定 digest |

## 8. 持续核对

以下项目不在自动化验收内，上线前应逐项确认：

- `sender.role` 是否仍被直接信任；管理员命令是否需要二次查询群成员信息。
- `admin_audit` 是否有保留期，避免成为长期行为档案。
- 数据库、日志、备份文件权限是否统一为 600，目录是否为 700。
- IPv6 ULA `fc00::/7`、IPv4-mapped IPv6 与 `0.0.0.0` 是否在图片地址校验中覆盖。
- 图片下载重定向是否逐跳重新校验。
- NapCat 是否固定镜像 digest、使用非 root UID/GID。
- 证书到期告警、依赖与镜像扫描、恢复演练是否有固定周期。
